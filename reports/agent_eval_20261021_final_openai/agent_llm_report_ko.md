# M5 Agent — LLM 정책 평가 보고

작성 2026-10-21 · 설정 `configs/agent_eval.json` · 주 모델 `gpt-4.1-2025-04-14`

## 0. 결론 세 줄

1. **규칙 기반 정책이 LLM 정책보다 점수가 높았다.** 최종 8문항에서 규칙 8/8, gpt-4.1 5/8, gpt-5-mini 4/8.
2. **실행기의 방어장치가 실제 LLM 을 상대로 작동했다.** gpt-4.1 이 도구가 준 `8.055` 를
   `8.06` 으로 바꿔 적자 답변이 반려됐다.
3. LLM 의 약점은 한 축에 몰려 있다. **언제 멈출지 모르는 것**(termination).
   도구 선택과 인용은 두 모델 모두 8/8 이었다.

## 1. 최종 결과 (final 8문항, 각 정책 1회)

| 축 | 규칙 기반 | gpt-4.1 | gpt-5-mini |
|---|---|---|---|
| 도구 선택 | 8/8 | **8/8** | **8/8** |
| 주장별 인용 | 8/8 | **8/8** | **8/8** |
| 오류 처리 | 8/8 | **8/8** | **8/8** |
| 정보 부족 선언 | 8/8 | 6/8 | **8/8** |
| 필수 고지 | 8/8 | 7/8 | 7/8 |
| **종료** | 8/8 | **6/8** | **4/8** |
| **전 축 통과** | **8/8** | **5/8** | **4/8** |

모델 선정은 **dev 결과로** 했다(gpt-4.1 6/6, gpt-5-mini 3/6). 주·보조 구분을 final 결과를
보기 전에 선언했고, 점수가 낮게 나온 보조 모델도 그대로 싣는다.

### 1.1 dev 가 final 을 과대평가했다

gpt-4.1 은 dev 에서 6/6 이었지만 final 에서 5/8 이었다. 개발 질문으로 고른 설정이
보지 않은 질문에서 그대로 유지되지 않는다는 뜻이다. **dev 점수를 성능으로 보고하면 안 된다.**

## 2. 가장 중요한 결과 — 방어장치가 실제로 작동했다

F1(아스피린, 적용 범위 밖)에서 gpt-4.1 의 답변이 **반려**됐다.

> 종료 사유: `answer_rejected_unsourced`
> 사유: 도구가 돌려주지 않은 수치: `['8.06']` in `'질의 분자의 EGFR pIC50 예측값은 8.06이다.'`

### 2.1 이것이 무엇이고 무엇이 아닌가

**날조가 아니다.** 도구는 `8.055` 를 돌려줬고 모델은 `8.06` 으로 **반올림**했다.
없는 값을 만든 것이 아니라 있는 값을 바꿔 적은 것이다. 과장해서 "LLM 이 수치를 지어냈다"고
쓰지 않는다.

**그래도 막은 것이 맞다고 본다.** 이 프로젝트는 측정값의 출처 추적을 전제로 한다.
답변의 숫자가 도구가 준 숫자와 다르면, 그 답변을 보고 원 출처로 되짚어갈 수 없다.
`8.06` 을 ChEMBL 이나 모델 산출물에서 찾으면 나오지 않는다.

**다만 과한 면도 있다.** 반올림 하나 때문에 적용 범위 고지까지 포함된 정상적인 답변 전체가
버려졌다. 규칙 기반 정책은 반올림을 하지 않으므로 이 문제를 드러낼 수 없었다.
**LLM 을 붙였기 때문에 발견된 설계 질문이다.**

### 2.2 지금 고치지 않는다

`configs/agent_eval.json` 의 금지 항목에 "final 질문의 점수를 본 뒤 정책을 고치고 그것을
최초 결과처럼 쓰는 것"이 있다. 검증 규칙을 느슨하게 바꾸면 F1 이 통과로 바뀐다.
그래서 **이번 점수는 그대로 두고** 다음 반복의 과제로 남긴다.

다음에 결정할 것: 유효숫자 허용 오차를 둘 것인가, 아니면 모델에게 "도구가 준 숫자를
그대로 옮겨 적어라"를 더 강하게 지시할 것인가.

## 3. 나머지 실패의 성격

### 3.1 F6 — 범위 밖 질문에 과도하게 검색했다 (실질적 약점)

"오시머티닙의 임상 3상 전체 생존 기간 중앙값"은 연결된 도구의 범위 밖이다.
gpt-4.1 은 **결론은 맞게** 냈다(정보 부족 선언). 그러나 거기까지 **5회**를 호출했다.
규칙 기반은 0회로 끝냈다.

gpt-5-mini 는 같은 질문에 6회를 쓰고 예산을 소진했다.

이것이 두 모델의 공통 약점이고 `termination` 축의 실패 대부분을 차지한다.
남은 예산을 매 턴 알려줘도(`[남은 도구 호출: N회]`) 완전히 해소되지 않았다.

### 3.2 F2 — 평가 기준에 다툼의 여지가 있다

`CHEMBL999999999`(없는 ID)에 대해 gpt-4.1 은 "기록이 없다"를 출처와 함께 답하고
`insufficient_information=false` 로 끝냈다. 기준은 `true` 를 기대했다.

"기록이 없다"는 것은 **정보 부족이 아니라 확인된 사실**이라고 볼 수도 있다.
D6 에서 같은 종류의 기준 오류를 이미 한 번 고쳤다. 다만 **final 질문이므로 지금 고치지 않는다.**
점수는 실패로 두고 기준의 모호함을 여기에 적어둔다.

판단에 영향을 주지 않도록 덧붙이면, 이 한 문항을 통과로 보더라도 gpt-4.1 은 6/8 로
규칙 기반 8/8 에 못 미친다. 결론은 바뀌지 않는다.

## 4. 모델 간 차이

| | gpt-4.1-2025-04-14 | gpt-5-mini-2025-08-07 |
|---|---|---|
| dev | 6/6 | 3/6 |
| final | 5/8 | 4/8 |
| 평균 호출 수(final) | 1.5회 | 2.9회 |
| `temperature` 고정 | 가능(0) | **불가** — 기본값 1 강제 |
| 실행 간 변동 | 거의 없음 | 큼 (D6 이 1회↔6회) |

`temperature` 를 고정할 수 없다는 점은 평가 도구로서 중요한 결격이다. gpt-5-mini 는
같은 질문에 매번 다른 경로를 탄다. 재현 가능한 평가를 하려면 고정 가능한 모델을 써야 한다.

API 가 `temperature` 를 거부하면 인자를 빼고 재요청하며, 그 사실을 실행 기록의
`temperature_dropped_by_api` 에 남긴다. 모델별 지원 여부를 코드에 적어두지 않는다.

## 5. 규칙 기반이 이긴 것을 어떻게 읽을 것인가

**"규칙 기반이 LLM 보다 낫다"는 일반화는 하지 않는다.** 이유는 세 가지다.

1. 질문 14개는 내가 만들었고, 규칙 기반 정책은 그 질문들과 같은 사람이 설계했다.
   질문이 규칙 정책의 설계 공간 안에 있다.
2. 규칙 정책은 이 도구 4개 밖으로 한 발도 못 나간다. 질문이 조금만 달라져도 무너진다.
   LLM 은 `aspirin → CHEMBL25` 처럼 규칙 정책이 못 하는 해석을 해냈다(D6).
3. 표본이 8문항이다. 5/8 과 8/8 의 차이를 구간으로 말할 만큼의 자료가 아니다.

말할 수 있는 것은 이것이다. **이 질문 집합·이 도구 구성·이 예산에서는 규칙 정책이
더 안정적으로 멈췄다.** 그리고 LLM 의 실패는 능력보다 **절제**의 문제였다.

## 6. 개발 과정에서 고친 것 — 절반이 내 결함이었다

LLM 정책의 dev 점수는 2/6 → 3/6 → 3/6(gpt-5-mini), 6/6(gpt-4.1) 으로 움직였다.
그 과정에서 고친 것 중 **셋은 내 구현 결함**이었다.

| # | 증상 | 원인 | 성격 |
|---|---|---|---|
| 1 | 분자 없이 호출했는데 pIC50 **8.057** 이 나옴 | RDKit 이 빈 문자열을 '원자 0개 분자'로 파싱해 `None` 을 돌려주지 않는다 | **내 도구 버그** |
| 2 | 같은 호출을 6회 반복해 예산 소진 | 도구 결과를 OpenAI 규약(assistant `tool_calls` → role `tool`)이 아니라 user 메시지로 전달. 모델이 자기 호출을 볼 수 없었다 | **내 프로토콜 오류** |
| 3 | 근거를 얻고도 계속 검색 | 모델에게 남은 예산을 알려주지 않았다 | 하네스 개선 |
| 4 | D6 을 오답 처리 | 규칙 정책의 한계(이름→ID 매핑 불가)를 정답으로 굳힌 기준 | **내 평가 기준 오류** |

1번은 규칙 정책이 **드러낼 수 없는** 버그였다. 규칙 정책은 애초에 빈 SMILES 로 호출하지 않는다.
LLM 이 예상 밖으로 호출해준 덕분에 발견됐고, 회귀 테스트로 고정했다.

4번은 모델이 잘한 것을 본 뒤 기준을 바꾼 것이 맞다. 그래서 어느 한쪽을 정답으로 만들지 않고
**양쪽 모두 허용**으로 고쳤고, 규칙 정책도 같은 기준으로 다시 측정해(6/6 유지) 같은 자로 쟀다.

## 9. 다음 반복의 과제

1. 반올림 허용 여부 결정 (§2.2). 지금 고치면 final 점수를 사후 조작하는 것이 된다.
