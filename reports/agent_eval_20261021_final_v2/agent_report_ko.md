# M5 근거 조회와 도구 선택 Agent — 1차 보고

작성 2026-10-21 · 설정 `configs/agent_eval.json` · 정책 **규칙 기반(LLM 아님)**

## 0. 먼저 분명히 할 것

**이번에 평가한 것은 LLM Agent 가 아니다.** 이 환경에 `ANTHROPIC_API_KEY`·`OPENAI_API_KEY` 가
모두 없어 LLM 을 실제로 호출하지 못했다. 대신

* 도구 4개를 **실제로 연결**하고
* 호출 예산·출처 강제·종료를 **실행기에서 강제**하고
* 개발·최종 질문을 분리한 **평가 하네스**를 만들고
* **규칙 기반 결정적 정책**으로 하네스를 검증했다.

LLM 정책은 같은 인터페이스(`decide() -> Action`)로 끼울 수 있게 두었고, 키가 없으면
**생성 시점에 실패**하게 했다. 키가 없을 때 조용히 규칙 기반으로 떨어지면 무엇을 돌렸는지
흐려지기 때문이다(`tests/test_agent_runner.py::test_llm_policy_fails_loudly_without_key`).

## 1. 연결한 도구 4개

`configs/project.json` 의 agent 사양을 그대로 따랐다.

| 도구 | 실제 연결 대상 | 돌려주는 것 |
|---|---|---|
| `predict_activity` | pilot22 RandomForest (`artifacts/agent_predictor_20261021`) | 예측 pIC50 + **적용 범위 판정** + M1 에서 측정된 한계 |
| `lookup_measurements` | ChEMBL REST (`/activity`) | 실측 활성 + 혼합 금지 고지 |
| `search_literature` | Europe PMC `/search` | 문헌 메타데이터 + 공개 접근 여부 |
| `fetch_evidence` | Europe PMC `/search` (DOI/PMID) | 서지 + **전문 접근 가능성** |

모든 결과는 `status`(ok / not_found / error / refused), `source_ids`, `caveats` 를 같은 모양으로 돌려준다.
찾지 못하면 `not_found` 로 돌려주고 빈 값을 그럴듯하게 채우지 않는다.

### 1.1 predict_activity 는 숫자만 돌려주지 않는다

22건으로 학습한 모델에서는 **숫자보다 적용 범위가 중요하다.** 그래서 이 도구는 예측값과 함께
질의 분자의 Murcko scaffold 가 학습 12개 안에 있는지, 학습 분자와의 최대 Tanimoto 가 얼마인지,
예측값이 학습 라벨 범위 안인지를 판정해 돌려준다. M1·M2 에서 측정된 한계
(평균 예측 대비 우위 미확정)도 고정 문구로 붙는다.

## 2. 실행기가 강제하는 것

정책이 무엇을 하든 실행기가 막는다. 이것이 이번 작업의 핵심이다.

| 규칙 | 동작 |
|---|---|
| `max_tool_calls: 6` | 초과하면 답변을 만들지 않고 `budget_exhausted` 로 종료 |
| `max_search_retries: 2` | 같은 도구 반복 실패 시 `retry_limit` 로 종료 |
| `require_source_ids: true` | 수치를 담은 주장에 출처가 없으면 **답변 반려** |
| `llm_may_invent_measurements: false` | 도구가 돌려주지 않은 수치가 답변에 있으면 **답변 반려** |

### 2.1 방어장치를 음성 테스트로 확인했다

정책이 올바른 경우만 시험하면 방어장치를 시험한 것이 아니다. 그래서 **일부러 수치를 지어내는
정책**을 넣어 막히는지 확인했다(`tests/test_agent_runner.py`, 9개).

| 시험 | 결과 |
|---|---|
| 도구가 돌려주지 않은 수치(0.07)를 출처를 달고 주장 | `answer_rejected_unsourced` 로 반려 |
| 도구가 돌려준 수치(22.4)를 출처 없이 주장 | `answer_rejected_unsourced` 로 반려 |
| 도구가 돌려준 수치를 출처와 함께 주장 | 통과 (거짓 양성 없음) |
| 무한 호출 정책 | 6회에서 `budget_exhausted`, 정보 부족 선언 |
| 항상 실패하는 도구 | `retry_limit` 로 종료 |
| 없는 도구 호출 | `unknown_tool` 로 보고, 추측하지 않음 |
| LLM 이 아닌 정책의 trace | `model` 이 `None` (모델 이름을 지어내지 않음) |

가장 중요한 문항은 **F1(아스피린)** 이었다. 적용 범위 밖 분자에 모델이 pIC50 **8.055** 라는
무의미한 값을 내놓는데, 답변이 그 숫자만 전하는지 한계를 함께 전하는지를 본다.

> 주장: 모델 예측 pIC50 는 8.055 이다. (출처: model:c6538d0d…, cohort:CHEMBL4258549)
> 주장: 학습 분자와의 최대 Tanimoto 유사도는 0.133 이고 scaffold 가 학습 범위에 없다.
> 고지: 질의 분자의 Murcko scaffold 가 학습에 쓰인 12개 scaffold 에 없다. 적용 범위 밖이다

F6(오시머티닙 임상 3상 생존기간)은 연결된 도구의 범위 밖이라 **도구를 한 번도 부르지 않고**
모른다고 답했다. F7(없는 DOI)은 서지를 지어내지 않고 정보 부족으로 끝냈다.

## 5. 이 8/8 을 과대평가하지 말 것

**직접 만든 질문에 결정적 규칙 정책이 만점을 받은 것은 Agent 품질의 증거가 아니다.**
질문이 정책의 설계 공간 안에 있기 때문에 나온 수치다. 의미 있는 것은 점수가 아니라

* 도구 4개가 실제 외부 서비스에 붙어 동작한다는 것
* 실행기가 **지어낸 수치를 실제로 막는다**는 것을 음성 테스트로 확인했다는 것
* 개발 과정에서 발견된 두 가지 실제 결함(한국어 질의, 실패 후 도구 갈아타기)을 고쳤다는 것

이다. LLM 정책을 끼우면 같은 질문·같은 채점으로 비교할 수 있고, 그때 비로소
"LLM Agent 를 평가했다"고 쓸 수 있다.

## 6. 개발 중 발견한 결함

### 6.1 출처 검증의 거짓 양성 (단위 테스트가 잡았다)

`IC50 는 22.4 nM 이다` 라는 정당한 주장이 반려됐다. 수치 추출 정규식이 **`IC50` 의 `50`** 을
측정값으로 보고, 도구 응답에 없는 수치라고 판정했기 때문이다.

앞선 수동 확인은 이 버그를 놓쳤다. ChEMBL 의 실제 응답에 `assay_description` 으로
"IC50" 문자열이 들어 있어 `50` 이 우연히 허용 집합에 포함됐기 때문이다.
**가짜 도구로 격리해 시험한 단위 테스트가 잡았다.**

수정: 글자에 붙은 숫자(`IC50`, `pIC50`, `C797S`, `CHEMBL4278815`)를 측정값에서 제외한다.

| 입력 | 추출되는 수치 |
|---|---|
| `IC50 는 22.4 nM 이다.` | 22.4 |
| `pIC50 는 7.936 이다` | 7.936 |
| `CHEMBL4278815 기록` | (없음) |
| `C797S 변이` | (없음) |

### 6.2 이 수정 때문에 최종 질문을 다시 돌렸다 — 공개 사항

검증 규칙이 바뀌었으므로 dev 와 final 을 모두 재실행했다.

| 실행 | dev | final |
|---|---|---|
| 수정 전 | 6/6 | 8/8 (`reports/agent_eval_20261021_final/`) |
| 수정 후 | 6/6 | 8/8 (`reports/agent_eval_20261021_final_v2/`) |

**점수는 바뀌지 않았다.** 이 수정은 평가 질문이 건드리지 않는 경로의 버그였고 단위 테스트가
발견한 것이지, 최종 점수를 보고 한 조정이 아니다. 두 실행 폴더를 모두 보존한다.

## 8. 외부 출처의 재현성 한계

ChEMBL 과 Europe PMC 는 **버전을 고정할 수 없다.** 호출 시점의 내용을 돌려주므로 같은 질의가
나중에 다른 결과를 줄 수 있다. 그래서 trace 에 호출 시각과 반환된 `source_ids` 를 함께 남긴다.
이 기록 없이 "재현 가능하다"고 쓰지 않는다.
