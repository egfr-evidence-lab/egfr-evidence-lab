기존 .venv는 그대로 사용한다. 다른 세션이라고 새로 만들 필요는 없다.
현재 동작 확인 명령:

PYTHONPATH=src .venv/bin/python -m egfr_lab check-config
PYTHONPATH=src .venv/bin/python -m egfr_lab plan

PYTHONPATH=src .venv/bin/python -m unittest discover -s tests -v

기대 결과:

- unittest: 테스트 메서드 3개 통과(구현 진척에 따라 이후 수는 증가 가능).

PYTHONPATH=src는 위 각 명령에 명시했으므로 셸 환경이 달라도 실행할 수 있다.
가상환경을 activate했다는 가정에 의존하지 않는다.
현재 시스템 python3는 프로젝트 권장 버전과 다를 수 있으므로 .venv/bin/python을 쓴다.

Python 3.11 또는 3.12를 준비한다. 위 명령의 python3.12는 설치한 버전에 맞춘다.
.venv는 Git에 들어 있지 않으므로 새 컴퓨터에서는 다시 만들어야 한다.
Windows에서는 .venv/Scripts/python.exe와 해당 셸의 환경변수 문법으로 조정한다.

위 뼈대 점검에는 외부 패키지 설치가 필요 없다.
실제 데이터·ML 작업을 시작할 때만 다음 설치를 수행한다:

.venv/bin/python -m pip install '.[ml]'
.venv/bin/python -m pip check
.venv/bin/python -c 'import httpx, pandas, numpy, scipy, sklearn, rdkit, pyarrow; print("ML imports OK")'

설치·import 확인이 끝나면 환경 버전 기록과 재현 가능한 lock 방식을 정한다.
현재 pyproject.toml의 optional-dependencies는 후보이며 검증된 lock이 아니다.
deep/literature/agent/cloud extras는 필요한 단계에서 따로 설치한다.
이 문서를 만드는 작업에서는 위 ML 패키지 설치를 실행하지 않았다.

6. 다음 세션에서 수행할 첫 작업: P0
============================================================

목표: 모델 학습 전에 ChEMBL EGFR 자료를 실제로 수집하고,
어떤 실험 코호트로 무엇을 예측할 수 있는지 확인한다.

권장 구현 순서:
1) 공식 API 응답을 소량 조회해 필드와 스키마를 확인한다.
2) target CHEMBL203 / 인간 / IC50 조건의 수집기를 작성한다.
3) 페이지네이션·재시도·타임아웃·진행 기록·재실행 시 중복 방지를 넣는다.
4) ChEMBL release, 시각, 요청 조건, 원자료 파일 SHA-256을 기록한다.
   수집 중 release가 바뀌면 고정 release 자료 또는 재수집을 검토한다.
5) activity / molecule / assay / document / variant의 연결을 확인한다.
   API에 로컬 분석 스키마와 같은 이름의 열이 있다고 가정하지 않는다.
6) 원 행 수, 고유 분자·실험·문헌 수, 결측·부등호·단위·중복을 집계한다.
7) 생화학/세포 형식, 정상형/명시 변이/불명확을 구분하는 검토표를 만든다.
8) 실험 맥락이 해석 가능한 하나의 학습 코호트를 제안한다.
   정상형 생화학 실험은 첫 후보이며, 표본 감사 전에 확정된 것은 아니다.
9) 실제 표본 수·scaffold 수·라벨 범위·문헌 편중을 보고한다.
10) 그 결과로 다음 모델링 단계의 범위를 결정한다.

P0 산출물 목표:
- 수집 코드와 재실행 가능한 CLI(명령 이름은 실제 구현 시 문서화)
- 원자료 및 release/요청/해시 매니페스트

7. 바꾸지 말아야 할 과학적 구분
============================================================

- CHEMBL203만으로 정상형/변이형을 구분할 수 없다.
  variant 메타데이터와 assay 설명·필요 시 원 논문을 확인한다.
  미상·충돌 자료를 정상형으로 임의 분류하지 않는다.
- IC50, Ki, Kd를 하나의 회귀 정답값으로 무조건 합치지 않는다.
- 생화학 실험과 세포 성장·생존 실험을 하나의 라벨로 합치지 않는다.
- 부등호 측정은 정확값 회귀 정답으로 만들지 않고 보존·별도 처리한다.
- confidence=9가 모든 실험 조건의 동질성을 보장하지 않는다.
- pIC50 = -log10(IC50 [mol/L]); nM라면 9-log10(IC50 [nM]).
- 화학 정규화에서 원 SMILES·입체정보와 처리 정책을 보존한다.
- 동일 분자 또는 반복 측정의 학습/테스트 누수를 막는다.
- 주 평가는 scaffold 분할, random 분할은 비교용이다.
- 최종 테스트를 튜닝·모델 선택에 사용하지 않는다.
- 주 지표는 MAE, 보조 RMSE·Spearman이다.
- 모델 비교의 paired 평가와 scaffold cluster 재표집은 계획 상태다.
  scipy bootstrap의 paired=True만으로 cluster bootstrap이 되지는 않는다.
- 모델 seed 변동과 테스트 표본 재표집 불확실성을 구분한다.
- EGFR IC50 예측을 환자 효과·임상 내성·TPD 분해 효능 예측으로 부르지 않는다.
- 예측값, 실제 관측값, 문헌 설명과 정보 부족을 구분해 출력한다.
- 논문의 모델을 EGFR에 적용한 것과 원 논문 성능 재현은 다르다.

10. Git / 공개 저장소 / 환경 관리
============================================================

- .venv, tmp, 원자료·중간 데이터, 큰 모델 파일과 .env는 기본 Git 제외다.
- 실험·데이터 공개가 필요하면 범위·라이선스·파일 크기를 검토한다.
- 비밀키나 인증 토큰을 파일·로그·커밋에 넣지 않는다.
- .DS_Store는 연구 파일이 아니며 커밋하지 않는다.
- 작업 시작 시 git status와 변경 파일을 읽고 다른 세션의 변경을 보존한다.
- 동시에 같은 코드를 수정하지 않도록 작업 범위를 구분한다.
- 새 작업 브랜치를 만들면 기본 prefix는 codex/를 사용한다.
- 사용자 요청 범위에서 커밋·push하고, 원격 변경이 있으면 먼저 확인한다.
  force push나 다른 변경의 삭제로 동기화하지 않는다.
- 새 터미널에서 인증 문제가 나면 GitHub CLI/SSH 인증을 확인한다.
  이 파일에 인증정보를 저장하지 않는다.

PDF 재생성은 선택 작업이다. 원고 수정이 없다면 기존 PDF를 그대로 사용한다.
재생성할 때 PDF 의존성과 임베딩 가능한 한글 TTF를 준비하고 렌더링을 검토한다.
폰트와 도구가 현재 Mac에 있다고 다른 컴퓨터에도 있다고 가정하지 않는다.
