6. 다음 세션에서 수행할 첫 작업: P0

8) 실험 맥락이 해석 가능한 하나의 학습 코호트를 제안한다.

7. 바꾸지 말아야 할 과학적 구분
============================================================

- CHEMBL203만으로 정상형/변이형을 구분할 수 없다.
  variant 메타데이터와 assay 설명·필요 시 원 논문을 확인한다.
  미상·충돌 자료를 정상형으로 임의 분류하지 않는다.
- IC50, Ki, Kd를 하나의 회귀 정답값으로 무조건 합치지 않는다.
- 생화학 실험과 세포 성장·생존 실험을 하나의 라벨로 합치지 않는다.
- 부등호 측정은 정확값 회귀 정답으로 만들지 않고 보존·별도 처리한다.
- confidence=9가 모든 실험 조건의 동질성을 보장하지 않는다.
- pIC50 = -log10(IC50 [mol/L]); nM라면 9-log10(IC50 [nM]).
- 화학 정규화에서 원 SMILES·입체정보와 처리 정책을 보존한다.
- 동일 분자 또는 반복 측정의 학습/테스트 누수를 막는다.
- 주 평가는 scaffold 분할, random 분할은 비교용이다.
- 최종 테스트를 튜닝·모델 선택에 사용하지 않는다.
- 주 지표는 MAE, 보조 RMSE·Spearman이다.
- 모델 비교의 paired 평가와 scaffold cluster 재표집은 계획 상태다.
  scipy bootstrap의 paired=True만으로 cluster bootstrap이 되지는 않는다.
- 모델 seed 변동과 테스트 표본 재표집 불확실성을 구분한다.
- EGFR IC50 예측을 환자 효과·임상 내성·TPD 분해 효능 예측으로 부르지 않는다.
- 예측값, 실제 관측값, 문헌 설명과 정보 부족을 구분해 출력한다.
- 논문의 모델을 EGFR에 적용한 것과 원 논문 성능 재현은 다르다.

- 동시에 같은 코드를 수정하지 않도록 작업 범위를 구분한다.
- 새 작업 브랜치를 만들면 기본 prefix는 codex/를 사용한다.

  force push나 다른 변경의 삭제로 동기화하지 않는다.
- 새 터미널에서 인증 문제가 나면 GitHub CLI/SSH 인증을 확인한다.
  이 파일에 인증정보를 저장하지 않는다.

[무엇을 했나]
Chemprop 저자 공개 `sampl` 벤치마크(물-옥탄올 logP)를 선택 C(환경 교체 + 예산 축소)로

배포본을 그대로 썼어. 설정은 실행 전에 고정했고 결과 JSON의 config_sha256 과 현재
설정 파일 해시가 일치함을 확인했어(실행 후 설정 수정 없음).

[결과 — 축소 조건에서의 결과이며 동일 조건 재현이 아니다]
  세트     n    우리RMSE   95%부트스트랩구간      저자보고   저자값이구간안에
  SAMPL6   11   0.3666     [0.2424, 0.4724]       0.27       예
  SAMPL7   22   0.6843     [0.3945, 0.9495]       0.49       예
  SAMPL9   16   1.0530     [0.7324, 1.3481]       1.11       예
  저자 분할 테스트: RMSE 0.5636 / MAE 0.3350 (저자 보고 랜덤 테스트셋 0.53)
  최적 검증 RMSE 0.5422 (epoch 43). 총 소요 약 55분, 5단계 모두 정상 종료.

세 세트 모두 저자 보고값이 우리 결과의 95% 구간 안에 들어와. 평가 세트가 11·22·16개
분자뿐이라 축소 조건의 결과와 저자 결과를 구별할 수 없어. 어느 방향으로도 우열을
주장하지 마. SAMPL9의 0.95배도 구간 폭 안의 변동이야.

[일치하지 않은 조건]
하이퍼파라미터 탐색 생략(저자 30회x50epoch), 앙상블 5->1, 데이터로더 워커 8->0,
실행 환경(python3.7.6/torch1.7.1/CUDA -> 3.12.14/2.5.1/CPU, macOS arm64).
epoch(split 50 / production 40)과 데이터·분할은 저자와 동일해.

[주의 1: production 로그의 test rmse 0.3416 을 성능으로 읽지 마]
저자 스크립트가 production 학습에서 val/test 경로에 학습 자료와 같은 파일을 지정해.
그 값은 내부 적합도(in-sample)야. 일반화 추정치는 저자 분할 테스트(0.5636)와 SAMPL 세트야.

[주의 2: 실행 중 장애 — 계산 완료 후 프로세스 미종료]
v1 설정(워커 저자 기본값 8)에서 split 학습이 12:01에 계산을 전부 끝내고
test_scores.csv·model.pt 까지 기록한 뒤에도 chemprop_train 프로세스가 종료되지 않아
파이프라인이 약 2시간 정지했어. macOS `sample` 로 네이티브 스택을 받아
Py_Exit -> Py_FinalizeEx -> finalize_modules -> slot_tp_finalize -> os_waitpid -> __wait4
블록을 확인했어. 학습 코드가 아니라 인터프리터 종료 처리 중 자식 프로세스 대기야.
전체 데이터 기준 2회 중 2회 재현됐어.

[다음 마일스톤 후보 — 부등호 5,482건]
회귀는 assay 조건에 민감해서 pooling 이 막혔어. 그런데 >10000 nM
(10uM 까지 50% 억제 없음)을 "비활성" 라벨로 쓰면 조건 민감도가 훨씬 낮은
과제가 돼. ATP 농도가 1uM 이든 10uM 이든 10uM 에서 안 듣는 화합물은
강한 저해제가 아니야. 그러면 원문 검증 없이도 수천 건 규모를 쓸 수 있어.
**22건 벽을 우회하는 유일한 경로로 보여.**

단 이것도 가정이야. "조건 민감도가 낮다"를 먼저 검증해야 해 —
같은 화합물이 여러 assay 에서 활성/비활성으로 갈리는 비율을 재면 돼.
그 데이터는 이미 있어. 새 마일스톤 규모니까 설정을 먼저 고정하고 시작해.
