# 1부. 기술 스택

## 1.1 데이터 수집 — 공개 API를 신뢰 가능하게 받아오기

대상은 ChEMBL REST API입니다. 단순히 요청을 보내는 것과, **나중에 검증 가능한 형태로** 받아오는 것은 다릅니다. 이 프로젝트에서 구현한 것은 뒤쪽입니다.

- **페이지네이션**: 결과가 많으면 API가 나눠서 줍니다. 전부 받을 때까지 반복합니다.
- **재개(resume)**: 중간에 끊겨도 이미 받은 응답은 다시 받지 않습니다. 기존 응답 429개의 해시가 유지되는지 확인한 뒤 나머지만 이어받았습니다.
- **원자적 저장**: 파일을 쓰다 중단되면 깨진 파일이 남습니다. 임시 파일에 쓴 뒤 교체하는 방식으로 막습니다.
- **release 고정**: ChEMBL은 주기적으로 갱신됩니다. 수집 시점의 버전(ChEMBL_37, 2026-05-01)을 기록해야 나중에 같은 자료인지 말할 수 있습니다.
- **매니페스트(manifest)**: 요청 조건, 응답 파일 수, 각 파일의 SHA-256 해시를 JSON으로 남깁니다. 이것이 있어야 "그때 받은 그 파일이 맞다"를 증명할 수 있습니다.

> **SHA-256이란**: 파일 내용을 64자리 문자열로 요약하는 함수입니다. 내용이 1바이트라도 바뀌면 전혀 다른 값이 나옵니다. 파일이 바뀌지 않았음을 증명하는 데 씁니다.

## 1.2 화학정보학 — RDKit

분자를 컴퓨터가 다루려면 숫자로 바꿔야 합니다.

- **SMILES**: 분자 구조를 글자로 쓰는 표기법. `CCO`는 에탄올입니다.
- **입체정보(stereochemistry)**: 원자 연결이 같아도 3차원 배치가 다르면 다른 분자이고 약효도 다릅니다. 임의로 지우면 안 됩니다.
- **Murcko scaffold(골격)**: 분자에서 곁가지를 떼고 고리와 연결부만 남긴 "뼈대". 비슷한 계열인지 판단하는 기준입니다.
- **connectivity group**: 입체정보를 무시하고 연결 구조만 같은 분자들을 묶은 그룹. 같은 분자의 거울상이 학습/평가에 나뉘어 들어가는 것을 막을 때 씁니다.
- **Morgan fingerprint**: 분자를 2048개의 0/1 비트로 바꿉니다. 이 프로젝트 설정은 반지름 2, 2048비트, 입체정보 포함입니다.
- **Tanimoto 유사도**: 두 fingerprint가 얼마나 겹치는지를 0~1로 나타냅니다. 0.8이면 "비슷하다"지 "정확도 80%"가 아닙니다.

## 1.3 머신러닝 — scikit-learn

- **DummyRegressor(기준선)**: 학습 데이터의 평균만 답하는 모델. **모든 모델은 이것보다 나아야 의미가 있습니다.** 기준선 없이 "MAE 0.3"만 제시하면 좋은지 나쁜지 알 수 없습니다.
- **RandomForest**: 결정 트리를 여러 개 만들어 평균내는 모델. 설정은 트리 300개, 리프 최소 2개.
- **GroupKFold(scaffold 분할)**: 데이터를 무작위로 나누지 않고, **같은 골격은 통째로 한쪽에만** 들어가게 나눕니다. 무작위로 나누면 학습셋의 유사체를 평가셋에서 맞히는 셈이라 성능이 부풀려집니다.
- **seed**: 난수 고정값. 42/123/2026 세 개로 돌려 결과가 seed에 따라 흔들리는 폭을 확인했습니다.

## 1.4 통계 해석 — 이 프로젝트의 핵심 교훈

실제 결과입니다. seed 42, scaffold 3-분할 기준:

| 모델 | MAE | RMSE |
|---|---|---|
| Dummy(평균) | 0.3096 | 0.3759 |
| RandomForest | 0.2950 | 0.3640 |
| 차이(RF − Dummy) | **−0.0146** | — |
| 차이의 95% 구간 | **[−0.0819, +0.0506]** | — |

RF가 숫자상 더 좋지만, **구간이 0을 포함**합니다. 이것은 "RF가 더 낫다고 말할 근거가 부족하다"는 뜻입니다. 표본이 22건이고 그중 11건이 한 골격이라 이 결과는 예상 범위입니다.

> **알아둘 점**: 면접이나 보고에서 이 결과를 숨기지 말고 먼저 말하는 편이 낫습니다. "모델이 실패했다"가 아니라 "표본 크기에서 기대되는 결과이고, 그것을 구간으로 확인했다"가 올바른 해석입니다. 숫자 하나만 보고 우열을 말하지 않는 태도가 통계 역량의 증거입니다.

- **bootstrap**: 가진 데이터를 반복 재추출해 추정값이 얼마나 흔들리는지 보는 방법. 이 프로젝트는 골격 단위로 2000회 재추출했습니다.
- **MAE / RMSE**: 평균 절대 오차 / 제곱평균제곱근 오차. RMSE가 큰 오차에 더 민감합니다.

## 1.5 재현성 — 나중에 남이 확인할 수 있게

- **설정 동결**: 결과를 보기 **전에** 분할·모델·seed를 JSON에 고정했습니다. 결과를 본 뒤 기준을 바꾸면 그건 검증이 아닙니다.
- **입출력 해시**: 모든 산출 폴더에 입력 파일과 출력 파일의 SHA-256을 기록합니다.
- **버전 폴더**: 기존 결과를 덮어쓰지 않고 `_v2`, `_v3`처럼 새 폴더에 씁니다.
- **독립 검증 스크립트**: 학습과 별개로, 저장된 모델 36개를 다시 불러와 예측이 일치하는지 확인하는 스크립트를 따로 둡니다.
- **테스트 52개**: 단위 변환, 부등호 처리, 누출 검사, 중간체 오연결 등 "하면 안 되는 일"을 테스트로 막아 둡니다.

## 1.6 출처 검증에 쓴 공개 API — 각각 무엇을 알려주는가

이 프로젝트에서 실제로 호출한 것들입니다. 어떤 질문에 어느 API를 쓰는지 아는 것이 실무 역량입니다.

| API | 알려주는 것 | 이번에 쓴 예 |
|---|---|---|
| ChEMBL REST | 측정값·분자·실험·문헌 연결 | 26,600건 수집 |
| Europe PMC | 논문 메타데이터, 전문 공개 여부 | `isOpenAccess`, `inEPMC`로 접근 가능 여부 판정 |
| Crossref | DOI 메타데이터, **참고문헌 목록** | 유료 논문의 참고문헌에서 실험 외주 업체 단서 확보 |
| OpenAlex | 논문의 공개 사본 위치 목록 | 기관 레포지토리 사본 발견 |
| figshare | ACS 논문의 **보충자료(SI)** 호스팅 | SI PDF를 제공자 MD5까지 확인해 확보 |
| RCSB PDB | 단백질 구조의 종·서열·변이·발현계 | 논문 본문 없이 "인간·정상형·696–1021" 확인 |
| Zenodo | 연구 데이터 아카이브, 체크섬 | 벤치마크 데이터 1.63GB·MD5 확인 |
| GitHub API | 저자 코드의 정확한 commit·설정 | 재현 대상 스크립트와 환경 파일 고정 |

**실무 요령**: 유료 논문이라도 (1) SI는 figshare에 공개된 경우가 많고, (2) 구조는 PDB에 기탁돼 있으며, (3) 참고문헌 목록은 Crossref로 볼 수 있고, (4) 기관 레포지토리에 사본이 있을 수 있습니다. 본문이 막혀도 확인할 수 있는 것이 생각보다 많습니다.

## 1.7 다음 단계에서 쓸 기술 (아직 미실행)

- **D-MPNN / Chemprop**: 분자를 그래프(원자=점, 결합=선)로 보고 메시지를 주고받으며 표현을 학습하는 신경망. fingerprint처럼 사람이 정한 규칙이 아니라 데이터에서 표현을 배웁니다.
- **구버전 환경 문제(실제로 마주침)**: 재현 대상 논문의 환경은 python 3.7.6 / torch 1.7.1 / CUDA 10.2(리눅스·NVIDIA)입니다. 이 Mac(Apple Silicon, CUDA 없음)에서는 그대로 설치할 수 없습니다. 또 저자 스크립트의 `mean_squared_error(squared=False)`는 scikit-learn 1.6에서 제거되어 최신 환경에서 그대로 돌아가지 않습니다.
- **교훈**: 재현은 "코드를 돌리는 일"이 아니라 **환경·데이터·설정·결과를 각각 맞추는 일**입니다. 맞출 수 없는 부분은 숨기지 말고 차이로 기록합니다.

# 2부. 도메인 지식

## 2.1 EGFR이 무엇이고 왜 중요한가

- **EGFR**(상피성장인자 수용체)는 세포 표면 단백질로, 신호를 받으면 세포 증식을 촉진합니다.
- 이 단백질에 돌연변이가 생기면 신호가 계속 켜져 암세포가 자랍니다. 특히 **비소세포폐암**에서 중요합니다.
- 따라서 EGFR의 효소 활성(인산화 효소, kinase)을 막는 약이 표적치료제가 됩니다.
- 식별자: ChEMBL `CHEMBL203`, UniProt `P00533`, 사람 taxid `9606`. 약이 붙는 **kinase 도메인**은 대략 잔기 696–1022 구간입니다.

## 2.2 IC50와 pIC50

- **IC50**: 효소 활성을 50% 억제하는 데 필요한 화합물 농도. **작을수록 강한 약**입니다.
- 값의 범위가 매우 넓어(수 nM ~ 수만 nM) 로그로 바꿔 씁니다.
- **pIC50 = −log₁₀(IC50 [mol/L])**. nM 단위라면 **pIC50 = 9 − log₁₀(IC50 [nM])**.
- 예: IC50 10 nM → pIC50 8.0. pIC50은 **클수록 강한 약**입니다(방향이 반대).
- 로그를 쓰는 이유: 10 nM과 20 nM의 차이와 10,000 nM과 20,000 nM의 차이를 같은 "2배"로 다루기 위해서입니다.

## 2.3 정상형(WT)과 내성 변이

- **WT(wild type, 정상형)**: 돌연변이가 없는 원래 단백질.
- **L858R**: 858번 류신이 아르기닌으로 바뀐 변이. 폐암에서 흔하고 1세대 약이 잘 듣습니다.
- **T790M**: 1세대 약을 쓰다 생기는 **내성** 변이. 약이 붙는 자리의 문지기(gatekeeper) 잔기가 바뀝니다.
- **C797S**: 3세대 약(오시머티닙)에 대한 내성 변이. 3세대 약이 공유결합하는 시스테인이 사라집니다.
- **중요**: 같은 화합물이라도 WT와 변이에서 IC50이 완전히 다릅니다. **표적 ID가 같다는 이유로 섞으면 안 됩니다.**
- 또한 WT를 **덜** 억제하는 것이 좋은 경우가 있습니다(정상 조직 부작용을 줄이려고). 그래서 "WT IC50이 낮다 = 좋은 약"이 아닙니다.

## 2.4 생화학 실험과 세포 실험

| 구분 | 생화학(biochemical) | 세포(cell-based) |
|---|---|---|
| 대상 | 정제한 효소 단백질 | 살아있는 세포 |
| 측정 | 효소 활성 억제 | 증식 억제, 신호 억제 |
| 지표 | IC50 | GI50, EC50, CC50 |
| 영향 요인 | ATP 농도, 기질, 온도 | 세포막 투과, 대사, 배양 시간 |

둘은 **다른 질문에 답하는 실험**이라 한 라벨로 합치면 안 됩니다. 이 프로젝트의 학습 대상은 생화학 IC50입니다.

## 2.5 실험 조건이 왜 결과를 바꾸는가 (가장 중요한 부분)

대부분의 EGFR 억제제는 **ATP와 경쟁해서** 같은 자리에 붙습니다. 그러면 ATP 농도가 결과를 바꿉니다.

- ATP를 많이 넣으면 경쟁이 심해져 **같은 약도 IC50이 커집니다(약해 보입니다)**.
- 이번에 실제로 확인한 ATP 농도: 승인 코호트 **5 µM**, 어떤 특허 **10 µM**, 어떤 논문 **1 mM**. 1 mM은 5 µM의 200배입니다.
- 따라서 **ATP 농도가 다른 실험의 IC50을 한 표에 합치면 안 됩니다.**

조건이 같아야 비교할 수 있는 항목들(이 프로젝트가 관리하는 13개):
종, 변이, 단백질 구성체, 효소 농도, ATP 농도, 기질, 기질 농도, 사전배양 시간, 반응 시간, 온도, 완충액 pH, 검출법, 억제 기전.

**검출법(readout)** 종류와 이번에 실제로 본 예:
- **ELISA**: 항체로 인산화된 기질을 검출 (승인 코호트)
- **Kinase-Glo / ADP-Glo**: 남은 ATP 또는 생성된 ADP를 발광으로 측정
- **TR-FRET / HTRF**: 두 형광 표지 사이 에너지 전달로 측정
- **Z′-LYTE**: 형광 기질의 절단 차이로 측정
- **방사성 ³³P**: 인산기를 방사성 표지로 직접 측정
- **Caliper(미세유체 이동도)**: 인산화로 전하가 바뀐 기질을 전기영동으로 분리

같은 화합물도 검출법이 다르면 값이 달라질 수 있습니다.

**공유결합(비가역) 억제제**는 추가 주의가 필요합니다. 효소에 영구히 결합하므로 **반응 시간이 길수록 더 세 보입니다.** 그래서 IC50 하나만으로 비교하면 왜곡됩니다. 사전배양 시간이 중요한 이유입니다.

## 2.6 섞으면 안 되는 것들 — 데이터 정제의 핵심 규칙

| 섞으면 안 되는 것 | 이유 |
|---|---|
| IC50 / Ki / Kd | 측정하는 물리량이 다름 |
| 생화학 / 세포 실험 | 질문이 다름 |
| WT / 변이 | 단백질이 다름 |
| ATP 농도·검출법이 다른 실험 | 값의 기준이 다름 |
| **부등호 값** (`>10,000 nM`) | 정확한 값이 아님. "최소한 이것보다 크다"일 뿐 |
| **구간의 중간값** | 예: 원 논문이 "A~E 구간"으로 보고한 것을 DB가 55/550/5500 nM처럼 중간값으로 적은 경우가 있었음. 이것을 정확값 회귀 정답으로 쓰면 안 됨 |
| **단일 농도 억제율** | "10 µM에서 85% 억제"는 IC50이 아님 |

이번 프로젝트의 자료에서 26,600건 중 관계기호 분포는 `=` 19,719 / `>` 3,309 / `<` 2,067 / 기타·결측 약 1,500건이었습니다. **약 26%가 정확값이 아닙니다.**

## 2.7 억제제와 분해제(PROTAC)는 다른 약

- **억제제**: 효소에 붙어 기능을 막습니다. 지표는 IC50.
- **분해제(PROTAC)**: 표적 단백질을 세포의 분해 장치로 끌고 가 **없애 버립니다**. 지표는 **DC50**(50% 분해 농도), **Dmax**(최대 분해율).
- 두 지표는 의미가 달라 한 라벨로 합칠 수 없습니다.

## 2.8 scaffold 분할이 필요한 이유와 그 한계

- 무작위로 나누면 같은 계열의 유사체가 학습과 평가 양쪽에 들어가 **성능이 부풀려집니다.**
- 그래서 골격 단위로 나눕니다. 이번 승인 코호트는 골격 중복 0으로 확인했습니다.
- **다만 한계가 있습니다**: 골격이 달라도 화학적으로는 매우 비슷할 수 있습니다. 이번 진단에서 골격 중복이 0인데도 가장 가까운 학습 분자와의 Tanimoto가 **0.986**인 경우가 있었습니다.
- 즉 "골격을 나눴다"가 "새로운 계열에도 통한다"를 보장하지 않습니다.

## 2.9 confidence score와 DB 주석을 믿는 정도

- ChEMBL의 `confidence_score 9`는 "표적 지정이 확실하다"는 의미이지, **실험 조건이 같다는 보장이 아닙니다.**
- 더 중요한 것: **DB 주석이 원 논문을 넘어설 수 있습니다.** 이번에 실제로 발견한 사례에서, DB 설명에는 "GST 태그, Sf9 곤충세포 발현"이 적혀 있었지만 **원 논문 전문에는 그런 서술이 전혀 없었고** 효소는 공급사 이름만 적혀 있었습니다. 기질 펩타이드 서열도 DB와 원문이 달랐습니다.
- **원칙**: DB와 원문이 충돌하면 어느 쪽도 오류로 단정하지 않고 양쪽을 보존한 채 보류합니다.

# 3부. 이번에 실제로 겪은 함정 5가지

1. **"오픈액세스" 링크가 논문이 아닐 수 있다.** 어떤 색인 서비스가 OA로 표시한 링크를 따라갔더니 논문 본문이 아니라 **그 논문에서 파생된 2차 데이터셋**이었습니다. 그것으로 원문을 검증했다고 하면 출처가 순환합니다.

2. **기관 레포지토리에 전문이 없을 수 있다.** PDF 링크로 보이는 주소가 실제로는 472바이트짜리 "저작권상 전문은 색인용으로만 제공" 안내 페이지였습니다. HTTP 200이라고 성공이 아닙니다. **받은 것의 내용과 형식을 확인해야 합니다.**

3. **보수적인 자동 규칙은 과검출한다.** 자동 분류기가 어떤 생화학 실험을 "세포 실험일 수 있음"으로 보류했는데, 원인은 설명에 있던 "**발현용** Sf9 곤충세포"였습니다. 단백질을 만든 세포이지 실험을 한 세포가 아닙니다. 규칙 기반 분류는 이런 과검출을 전제하고 사람이 재검토해야 합니다.

4. **질량이 맞아도 구조가 맞는 것은 아니다.** 특허의 질량분석값과 DB 구조의 계산 질량을 대조했는데, 맞는 경우에도 **위치이성질체·입체이성질체는 구별되지 않습니다.** 질량 일치를 구조 검증으로 쓰면 안 됩니다.

5. **재현 환경은 생각보다 빨리 낡는다.** 2년 전 논문의 환경(python 3.7, torch 1.7.1, CUDA 10.2)은 지금 Apple Silicon Mac에 설치되지 않습니다. 저자 스크립트가 쓰는 라이브러리 인자 하나(`squared=False`)도 이후 버전에서 삭제됐습니다. **재현 가능성은 코드 공개만으로 보장되지 않습니다.**
