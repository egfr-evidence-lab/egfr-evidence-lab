# EGFR Evidence Lab 학습 가이드

이 프로젝트를 하면서 실제로 마주친 의학·메디컬 도메인 지식과 AI 기술을 정리했습니다. 교과서 요약이 아니라 **이 프로젝트의 어느 지점에서 그 지식이 필요했는지**를 함께 적었습니다. 외워야 할 목록이 아니라, 판단이 필요했던 자리의 기록입니다.

수치는 전부 이 프로젝트의 실제 산출물에서 가져왔습니다. 추정이나 예시가 아닙니다.

## 1부. 의학·메디컬 도메인 지식

### 1.1 EGFR이 무엇이고 왜 이 표적인가

EGFR(Epidermal Growth Factor Receptor, 상피성장인자 수용체)은 세포막을 관통하는 수용체 티로신 키나아제입니다. 세포 밖에서 성장인자가 붙으면 세포 안쪽의 키나아제 영역이 활성화되고, 그 신호가 세포 증식으로 이어집니다.

이 수용체에 돌연변이가 생겨 신호가 꺼지지 않으면 세포가 계속 증식합니다. 비소세포폐암(NSCLC)의 일부가 이 경로에 의존하며, 그래서 EGFR 키나아제를 막는 약이 치료제로 쓰입니다.

**이 프로젝트에서**: ChEMBL의 표적 ID `CHEMBL203`이 인간 EGFR입니다. 여기에 연결된 IC50 측정 26,600건, 분자 14,776개, 실험(assay) 2,425개, 문헌 1,299편을 수집했습니다.

### 1.2 활성 지표 — IC50, Ki, Kd, pIC50

| 지표 | 뜻 | 성격 |
|---|---|---|
| IC50 | 활성을 50% 억제하는 농도 | 실험 조건에 따라 변한다 |
| Ki | 억제 상수(결합 친화도) | 기질 농도를 보정한 값 |
| Kd | 해리 상수 | 결합만 본 값, 억제가 아님 |
| EC50 | 50% 효과를 내는 농도 | 작용제·길항제 모두 |
| GI50 | 세포 성장을 50% 억제하는 농도 | 세포 수준 |

IC50은 **작을수록 강한 저해제**입니다. 농도 단위(nM)라 값이 커질수록 약한 쪽이어서 직관과 반대입니다. 그래서 로그로 변환합니다.

```
pIC50 = -log10(IC50 [M]) = 9 - log10(IC50 [nM])
```

IC50 10 nM이면 pIC50 = 8입니다. pIC50은 **클수록 강한** 저해제이고, 분포가 정규에 가까워져 회귀에 쓰기 좋습니다.

**섞으면 안 되는 이유**: IC50과 Ki는 정의가 다릅니다. Ki는 Cheng-Prusoff 식으로 IC50에서 환산할 수 있지만 기질 농도와 Km을 알아야 하고, 논문에 그 값이 없으면 환산이 불가능합니다. 이 프로젝트는 **IC50만** 다루고 Ki·Kd와 합치지 않았습니다(`configs/project.json`의 `pool_ic50_ki_kd: false`).

### 1.3 생화학 실험과 세포 실험은 다른 양이다

같은 "IC50"이라도 무엇을 측정했는지가 다릅니다.

| 구분 | 측정 대상 | 영향 요인 |
|---|---|---|
| 생화학(biochemical) | 정제한 효소의 활성 억제 | 효소·ATP·기질 농도, 완충액 |
| 세포(cell-based) | 살아 있는 세포의 반응 | 세포막 투과성, 유출 펌프, 대사, 혈청 단백 결합 |

세포 실험 IC50은 보통 생화학보다 큽니다. 약이 세포 안까지 들어가야 하기 때문입니다. 두 값을 한 라벨로 합치면 모델이 "화합물의 저해 능력"이 아니라 "저해 능력 + 투과성의 뒤섞임"을 배웁니다.

**이 프로젝트에서**: ChEMBL의 `assay_type`으로 구분했습니다. 수집한 2,425개 assay 중 생화학(B) 2,264개, 기능(F) 104개, ADME(A) 55개, 독성(T) 2개였습니다. `bao_label`로 측정 형식을 더 좁혀 단일 단백질 형식 1,509개 / 세포 기반 606개를 구분했습니다. 학습에는 **생화학 + 단일 단백질 형식만** 썼습니다.

### 1.4 변이 — 내성의 진화를 읽는 법

EGFR 저해제의 역사는 내성 변이와의 경쟁입니다.

| 변이 | 위치·성격 | 임상적 의미 |
|---|---|---|
| **L858R** | exon 21, 활성화 변이 | 1세대 저해제(gefitinib, erlotinib)가 잘 듣는다 |
| exon 19 deletion | 활성화 변이 | 1세대 감수성 |
| **T790M** | gatekeeper 위치 | 1세대 내성. 3세대(osimertinib)가 표적 |
| **C797S** | 공유결합 부위의 시스테인 소실 | 3세대 내성. 공유결합 자체가 불가능해진다 |
| L861Q, G719X | 비전형 활성화 변이 | 반응이 변이마다 다르다 |
| exon 20 insertion | 입체 구조 변화 | 전통적 저해제에 잘 듣지 않는다 |

C797S가 특히 중요합니다. 3세대 저해제는 C797 잔기에 **공유결합**해서 작동하는데, 그 시스테인이 세린으로 바뀌면 결합할 대상 자체가 없어집니다. 그래서 4세대 저해제나 분해제(degrader) 전략이 연구됩니다.

**이 프로젝트에서**: 수집한 assay 2,425개 중 616개에 변이가 표기돼 있었고 표기는 12종이었습니다.

| 변이 표기 | assay 수 |
|---|---|
| L858R, T790M | 203 |
| L858R | 116 |
| UNDEFINED MUTATION | 115 |
| L858R, T790M, C797S | 90 |
| T790M | 70 |
| L861Q | 9 |
| T790M, C797S | 5 |
| C797S / C797S,L858R / G719C | 각 2 |
| T790M,L858M / G719S | 각 1 |

이 분포는 ChEMBL assay의 변이 표기이며 **임상 빈도가 아닙니다**. 연구가 많이 된 변이가 많이 나타납니다.

**`UNDEFINED MUTATION` 115건이 중요한 함정입니다.** 변이가 있다고만 적혀 있고 무엇인지 모릅니다. 정상형으로도, 특정 변이로도 쓸 수 없습니다. 이 프로젝트는 `unknown_variant_is_wild_type: false`로 고정했습니다 — **모르는 것을 정상형으로 가정하지 않는다**는 뜻입니다.

### 1.5 부등호 관측 — `>10000 nM`은 측정값이 아니다

ChEMBL의 `standard_relation`에는 등식 외에 부등호가 들어옵니다.

| 관계 | 측정 건수 | 뜻 |
|---|---|---|
| `=` | 19,719 | 값을 측정했다 |
| `>` | 3,309 | 그 농도까지 올려도 50% 억제가 안 됐다 |
| `<` | 2,067 | 가장 낮은 시험 농도에서도 이미 억제됐다 |
| `<=` | 87 | 상한 |
| `>>` | 11 | 훨씬 크다 |
| `>=` | 8 | 하한 |

`>10000 nM`을 10000으로 적어 회귀에 넣으면 **그 화합물이 10 µM에서 정확히 반 억제된다고 가르치는 것**입니다. 사실은 "10 µM까지는 효과가 없었다"입니다. 실제 값은 10 µM보다 크고, 얼마나 큰지 모릅니다.

이것은 통계학에서 **중도절단(censored) 데이터**입니다. 제대로 다루려면 생존분석류의 방법이 필요하고, 단순 회귀로는 처리할 수 없습니다.

**이 프로젝트에서**: 등식만 남겼습니다. 26,600건에서 19,719건으로 줄었습니다. 부등호 관측 5,482건을 버린 것이 아니라 **별도로 보존**했습니다 — 분류 문제로 쓸 수 있는 자료입니다.

### 1.6 실험 조건 — 같은 IC50이 왜 다른 양인가

생화학 IC50을 결정하는 조건들입니다.

| 조건 | 왜 중요한가 |
|---|---|
| 효소 농도 | 너무 높으면 저해제가 소진돼 IC50이 과대평가된다 |
| **ATP 농도** | ATP 경쟁 저해제는 ATP가 많을수록 IC50이 커진다 |
| 기질 종류·농도 | 펩타이드 기질마다 Km이 다르다 |
| 전처리(preincubation) 시간 | 느린 결합 저해제·공유결합 저해제에 결정적이다 |
| 반응 시간 | 공유결합 저해제는 시간이 길수록 강해 보인다 |
| 온도·pH | 효소 활성과 화합물 안정성에 영향 |
| 검출 방식 | 방사성, 형광, 발광 — 간섭 양상이 다르다 |
| 효소 구조체 | 키나아제 영역만 vs 전장 단백질 |

ATP 경쟁 저해제의 IC50은 ATP 농도에 따라 몇 배씩 달라집니다. 어떤 논문은 1 µM ATP, 어떤 논문은 10 µM ATP를 쓰는데, 같은 화합물이 다른 IC50으로 보고됩니다. **조건을 모르면 두 값을 비교할 수 없습니다.**

**이 프로젝트에서**: `configs/cohort_policy.json`에 13개 필수 필드를 정의했습니다 — species, variant, protein_construct, enzyme_concentration, atp_uM, substrate, substrate_concentration, preincubation_minutes, reaction_minutes, temperature_C, buffer_pH, readout, inhibitor_scope. **값이 빠진 것을 같다고 보지 않는다**(`missing_values_count_as_equal: false`)고 못박았습니다.

결과적으로 **cross-assay pooling 승인 0쌍**이 됐습니다. 선정 기준을 모두 통과한 측정이 5,511건·assay 558개나 남았는데, 조건이 같다고 원문으로 확인한 조합이 하나도 없어 **단일 assay 22건만** 학습에 썼습니다. 이것이 이 프로젝트의 가장 큰 제약이고, 동시에 가장 정직한 선택입니다.

### 1.7 ChEMBL 데이터 구조

| 테이블 | 내용 | 이 프로젝트의 규모 |
|---|---|---|
| activities | 측정 한 건 | 26,600행 × 32열 |
| assays | 실험 조건 | 2,425행 × 19열 |
| molecules | 분자 구조 | 14,776행 × 6열 |
| documents | 문헌 서지 | 1,299행 × 8열 |

추적 체인은 이렇게 이어집니다.

```
분자(molecule_chembl_id) → 측정(activity_id) → 실험(assay_chembl_id) → 문헌(document_chembl_id → DOI)
```

`activity_id`를 알면 ChEMBL 원본 한 건까지 되짚을 수 있습니다. 이 연결이 "근거 추적"의 기술적 토대입니다.

**품질 플래그**도 중요합니다.

| 플래그 | 뜻 | 건수 |
|---|---|---|
| `confidence_score` | 표적 지정 신뢰도 (9가 최고) | 9점 1,972 assay / 8점 453 assay |
| `data_validity_comment: Outside typical range` | 비정상적으로 크거나 작은 값 | 445 |
| `data_validity_comment: Potential transcription error` | 전사 오류 의심 | 65 |
| `potential_duplicate` | 중복 입력 의심 | 2,744 |
| `pchembl_value` | ChEMBL이 계산한 pIC50 | 19,378 / 26,600 |

`pchembl_value`가 7,222건에 없는 이유 중 하나가 부등호 관측입니다. ChEMBL도 부등호 값에는 pChEMBL을 매기지 않습니다.

### 1.8 신약개발 맥락 — 22건이 어디서 왔는가

의약화학 논문의 전형적 흐름입니다.

1. **선별(screening)**: 수백~수천 화합물을 단일 농도에서 시험
2. **히트 확정**: 억제율이 기준을 넘는 것만 농도-반응 곡선 측정 → IC50
3. **리드 최적화**: 구조를 조금씩 바꿔가며 활성·선택성·물성 개선
4. 세포 실험 → 동물 → 임상

이 프로젝트가 쓴 22건은 **2단계의 결과**입니다. `configs/cohort_scope_review.json`에 기록했듯, 후보로 검토한 자료 중 하나는 "10 µM에서 억제율 90% 초과인 화합물만 6점 농도반응 IC50 측정으로 진행"하는 선별이었습니다.

**이것이 선택 편향입니다.** 활성이 좋은 것만 IC50이 측정되므로, 라벨 분포가 좁고 높은 쪽에 몰립니다. 이 프로젝트의 22건도 pIC50 6.85~8.49(폭 1.65)에 모여 있습니다. 모델이 배울 변동폭 자체가 작습니다.

### 1.9 logP와 logD — M3에서 다룬 물성

M3에서 재현한 공개 벤치마크는 활성이 아니라 **분배계수**였습니다.

| 지표 | 정의 | 주의 |
|---|---|---|
| logP | 중성 분자의 옥탄올/물 분배계수 | pH와 무관한 중성 종의 값 |
| logD | 특정 pH에서의 분배계수 | 이온화를 포함, pH 명시 필요 |

측정법도 다릅니다. shake-flask(흔들어 분배시킨 뒤 양쪽 농도 측정)와 전위차 적정(potentiometric titration)이 다른 값을 줄 수 있습니다. SAMPL 챌린지는 물-옥탄올 logP 예측을 겨루는 공개 대회입니다.

logP는 약물 유사성 지표(흡수·투과·대사)의 핵심이며, ADME(흡수·분포·대사·배설)의 "A"와 직결됩니다.

### 1.10 분해제(degrader) 지표 — M4의 맥락

C797S 같은 내성 변이에는 저해제 대신 **표적 단백질 분해** 전략이 쓰입니다. PROTAC(proteolysis targeting chimera)은 표적과 E3 리가아제를 동시에 붙잡아 표적을 분해시킵니다.

| 지표 | 뜻 |
|---|---|
| DC50 | 표적을 50% 분해하는 농도 |
| Dmax | 달성 가능한 최대 분해율 |

**IC50과 DC50은 완전히 다른 양입니다.** IC50은 활성 억제, DC50은 단백질 양의 감소입니다. 섞어서 한 모델에 넣을 수 없습니다. 이 프로젝트는 `pool_inhibition_and_degradation_labels: false`로 고정했습니다.

M4(기업 문헌 사례)가 이 영역이었고, 원문을 확보하지 못해 보류했습니다.

## 2부. AI·기술 지식

### 2.1 분자를 컴퓨터에 넣는 방법

| 표현 | 성격 | 용도 |
|---|---|---|
| **SMILES** | 분자를 문자열로 | 입력 형식. 같은 분자에 여러 표기 가능 |
| canonical SMILES | 정규화된 하나의 표기 | 중복 확인 |
| **InChIKey** | 27자 해시 | 정확한 동일성 비교 |
| **Murcko scaffold** | 고리와 연결부만 남긴 골격 | 계열 구분, 분할 |
| **Morgan fingerprint** | 부분구조 존재를 비트로 | 모델 입력 벡터 |

Morgan fingerprint(ECFP와 유사)는 각 원자 주변을 반지름 r까지 훑어 부분구조를 해시해 고정 길이 비트벡터로 만듭니다. 이 프로젝트는 r=2, 2048비트, 입체화학 포함으로 고정했습니다.

```python
gen = rdFingerprintGenerator.GetMorganGenerator(radius=2, fpSize=2048, includeChirality=True)
```

**실제로 겪은 함정**: 빈 문자열 `""`을 RDKit에 넣으면 `None`이 아니라 **원자 0개 분자**로 파싱됩니다. 그 상태로 fingerprint를 만들면 전부 0인 벡터가 나오고, 모델은 아무렇지 않게 예측값을 돌려줍니다. 실제로 빈 SMILES에 pIC50 8.057이 나왔습니다. 그래서 명시적으로 막았습니다.

```python
if not smiles or not smiles.strip():
    return None, None
mol = Chem.MolFromSmiles(smiles)
if mol is None or mol.GetNumAtoms() == 0:
    return None, None
```

이 결함은 **LLM이 예상 밖 입력을 보내준 덕에** 발견됐습니다. 규칙 기반 테스트로는 드러나지 않았습니다.

### 2.2 Tanimoto 유사도와 적용 범위

두 fingerprint의 유사도는 Tanimoto 계수로 잽니다.

```
T(A, B) = |A ∩ B| / |A ∪ B|
```

0이면 공통 부분구조가 없고, 1이면 같습니다. 0.85 이상을 "유사"로 보는 관행이 있지만 데이터셋에 따라 다릅니다.

**적용 범위(applicability domain)**는 모델의 예측을 믿을 수 있는 입력 영역입니다. 이 프로젝트는 세 기준을 썼습니다.

1. 질의 분자의 Murcko scaffold가 학습 12개 안에 있는가
2. 학습 분자와의 최대 Tanimoto가 0.5 이상인가
3. 예측값이 학습 라벨 범위(6.85~8.49) 안인가

**이것이 왜 필수인지 실제로 확인했습니다.** 구조가 전혀 다른 분자 10개를 넣어봤습니다.

| 분자 | 예측 pIC50 | 환산 IC50 | 최대 Tanimoto |
|---|---|---|---|
| 포도당 | 8.048 | 약 9 nM | 0.045 |
| 에탄올 | 8.054 | 약 9 nM | 0.053 |
| 벤젠 | 8.055 | 약 9 nM | 0.028 |
| 아스피린 | 8.055 | 약 9 nM | 0.133 |
| 카페인 | 8.057 | 약 9 nM | 0.110 |
| 니코틴 | 8.143 | 약 7 nM | 0.163 |

예측값 폭이 **0.095**, 표준편차 **0.035**입니다. 학습 라벨 표준편차 0.381의 **9%**입니다.

**적용 범위 밖에서 이 모델은 입력에 거의 반응하지 않습니다.** 숫자만 돌려주는 API였다면 포도당이 9 nM EGFR 저해제로 보고됐을 것입니다. 그래서 서비스 응답에서 적용 범위 판정과 고지를 **생략할 수 없게** 설계했습니다.

### 2.3 분할 전략 — random과 scaffold는 다른 질문이다

| 분할 | 방법 | 답하는 질문 |
|---|---|---|
| random | 측정을 무작위로 나눔 | 같은 계열의 비슷한 분자를 맞출 수 있나 |
| **scaffold** | 같은 골격을 한 쪽에만 | **새로운 계열로 일반화되나** |

신약개발에서 중요한 것은 두 번째입니다. 이미 아는 계열의 변형체를 맞추는 것보다, 본 적 없는 골격을 평가하는 능력이 가치 있습니다.

scaffold 분할이 **훨씬 어렵고** 점수가 낮게 나옵니다. 그래서 random 분할 점수만 보고하면 성능을 과장하게 됩니다.

**이 프로젝트에서 실제로 결론이 갈렸습니다.**

| 분할 | seed | RF−Dummy MAE 차이 | 95% 구간 | 판정 |
|---|---|---|---|---|
| scaffold | 42 | −0.0146 | −0.0819 ~ +0.0506 | 0 포함 — 미확정 |
| scaffold | 123 | −0.0095 | −0.0766 ~ +0.0639 | 0 포함 — 미확정 |
| scaffold | 2026 | −0.0170 | −0.0906 ~ +0.0513 | 0 포함 — 미확정 |
| random | 42 | −0.0525 | −0.1143 ~ **−0.0047** | **0 제외 — 차이 있음** |
| random | 123 | −0.0472 | −0.1083 ~ +0.0111 | 0 포함 |
| random | 2026 | −0.0437 | −0.1118 ~ +0.0068 | 0 포함 |

random 분할 seed 42만 보면 "RF가 유의하게 낫다"고 쓸 수 있습니다. 주 지표인 scaffold 분할에서는 **세 seed 모두 미확정**입니다. 어느 쪽을 주 지표로 **먼저** 정해두지 않으면 결과를 보고 유리한 쪽을 고르게 됩니다.

### 2.4 데이터 누출과 GroupKFold

누출(leakage)은 테스트 정보가 학습에 새는 것입니다. 분자 데이터에서 흔한 형태들입니다.

- 같은 분자가 학습과 테스트에 동시에 (중복, 염 형태, 입체이성질체)
- 같은 scaffold가 양쪽에 (계열 정보 누출)
- 같은 문헌·같은 assay의 측정이 양쪽에 (조건 정보 누출)

scikit-learn의 `GroupKFold`는 그룹이 폴드를 넘지 않게 나눕니다. 이 프로젝트는 scaffold를 그룹으로 썼습니다. 입체이성질체는 누출 검사에서 한 그룹으로 묶었습니다(`group_stereo_variants_together_for_leakage_checks: true`).

### 2.5 기준 모델 — Dummy가 가장 중요한 모델이다

`DummyRegressor(strategy="mean")`는 **항상 학습 데이터의 평균**을 돌려줍니다. 입력을 전혀 보지 않습니다.

이것이 바닥선입니다. 복잡한 모델이 Dummy를 이기지 못하면 **그 모델은 아무것도 배우지 못한 것**입니다.

이 프로젝트의 scaffold 분할 MAE입니다.

| 모델 | MAE (seed 42 / 123 / 2026) |
|---|---|
| Dummy | 0.3096 / 0.3096 / 0.3096 |
| RandomForest | 0.2950 / 0.3001 / 0.2925 |
| D-MPNN | 0.3090 ~ 0.3111 |

RF가 약간 낮지만 신뢰구간이 0을 포함합니다. D-MPNN은 Dummy와 거의 같습니다. **22건으로는 어떤 모델도 평균 예측을 확실히 넘지 못했습니다.**

Dummy의 Spearman이 음수(−0.101)인 것도 의미 있습니다. 상수를 예측하면 순위 상관이 정의되지 않거나 잡음이 됩니다.

### 2.6 D-MPNN — 분자 그래프 신경망

D-MPNN(Directed Message Passing Neural Network)은 분자를 그래프로 보고 표현을 학습합니다.

```
원자 = node, 결합 = edge
→ 방향성 결합 메시지 전달 (depth 단계 반복)
→ 분자 전체 표현으로 집계 (readout)
→ 회귀 출력 (feed-forward)
```

Morgan fingerprint는 **사람이 정한 규칙**으로 부분구조를 센 것이고, D-MPNN은 **데이터에서 표현을 학습**합니다. 데이터가 충분하면 후자가 유리하다고 보고됩니다.

**이 프로젝트에서는 유리하지 않았습니다.** paired 비교 12개 중 11개의 신뢰구간이 0을 포함했습니다. 원인을 분석했더니 예측값의 표준편차가 0.011~0.036이었습니다. 관측 라벨의 표준편차는 0.377입니다.

**상수 붕괴(constant collapse)**입니다. 표본이 너무 적어 모델이 "평균을 내놓는 것이 가장 안전하다"는 해로 수렴했습니다. 흥미롭게도 M6에서 RandomForest도 적용 범위 밖에서 같은 현상을 보였습니다(2.2절). 모델 종류의 문제가 아니라 **22건·12 scaffold라는 규모**가 의심됩니다.

**구현에서 겪은 함정**: Chemprop v1의 `--seed`는 **데이터 분할 시드**이고 모델 초기화 시드가 아닙니다. 모델 쪽은 `--pytorch_seed`(기본 0)입니다. 이걸 모르고 `--seed`만 바꿨을 때 seed 간 예측 차이가 7.2e-05였습니다. `--pytorch_seed`를 제대로 전달하자 4.0e-02로 늘었습니다. **"seed를 바꿨는데 결과가 거의 같다"는 것은 seed가 적용되지 않았다는 신호입니다.**

### 2.7 통계 — 신뢰구간이 0을 포함한다는 말의 뜻

평가 지표들입니다.

| 지표 | 성격 | 주의 |
|---|---|---|
| MAE | 평균 절대 오차 | 해석이 직관적, 이상치에 둔감 |
| RMSE | 제곱평균제곱근 오차 | 큰 오차에 민감 |
| Spearman | 순위 상관 | 값보다 순서가 중요할 때 |

점수 하나만 보면 "RF 0.295 < Dummy 0.310이니 RF가 낫다"가 됩니다. 하지만 **표본이 22건입니다.** 다른 22건을 뽑으면 순서가 바뀔 수 있습니다.

**부트스트랩**은 가진 데이터에서 복원추출로 가상의 재표본을 만들어 지표의 변동폭을 추정합니다. 이 프로젝트는 2000회, scaffold 단위로 재표집했습니다. **분자 단위가 아니라 scaffold 단위**인 이유는 같은 골격의 분자들이 독립이 아니기 때문입니다.

paired 비교는 **같은 테스트 분자에 대한 두 모델의 오차 차이**를 봅니다. 모델별 점수를 따로 비교하는 것보다 검정력이 높습니다.

그 차이의 95% 구간이 0을 포함하면:

> 이 데이터로는 두 모델의 차이를 확정할 수 없다.

"차이가 없다"는 증명이 아닙니다. **"있는지 없는지 이 표본으로는 말할 수 없다"**입니다. 이 구분이 중요합니다. 전자는 강한 주장이고, 후자는 불확실성의 정직한 보고입니다.

### 2.8 재현성 — 해시, 버전, 사전 등록

이 프로젝트가 쓴 장치들입니다.

| 장치 | 방법 | 막는 문제 |
|---|---|---|
| 설정 고정 | 실행 **전에** JSON으로 동결, SHA-256 기록 | 결과를 보고 기준을 고치는 것 |
| 데이터 해시 | 코호트 파일 SHA-256 | 다른 데이터로 바뀐 것을 모르는 것 |
| 모델 해시 | joblib 파일 SHA-256 | 다른 모델이 서비스되는 것 |
| 버전 폴더 | 기존 출력 덮어쓰기 거부 | 이전 결과가 사라지는 것 |
| 의존성 고정 | 해시 lock, 컨테이너 내부 freeze | "내 기계에서는 됐는데" |
| 베이스 이미지 digest | 태그가 아닌 digest로 고정 | 같은 태그의 내용이 바뀌는 것 |
| 독립 검산 | 별도 스크립트로 지표 재계산 | 계산 코드 자체의 오류 |

**사전 등록(pre-registration)**이 특히 중요합니다. 측정 전에 예상을 적어두고, 결과를 본 뒤 그 예상을 고치지 않습니다.

M6에서 실제로 적어둔 예상과 결과입니다.

| 항목 | 사전 예상 | 실제 | 판정 |
|---|---|---|---|
| 호스트 p50 | 5~30 ms | 9.348 ms | 맞음 |
| 컨테이너 p50 | 10~60 ms | 11.610 ms | 맞음 |
| 컨테이너 모델 로딩 | 1~5 초 | 0.844 초 | **틀림** |
| 클라우드 콜드 스타트 | 2~15 초 | 0.13 초 | **틀림** |
| 클라우드 모델 로딩 | 0.5~3 초 | 4.998 초 | **틀림** |
| 이미지 push | 3~20 분 | 약 1 분 | **틀림** |

7개 중 4개가 틀렸습니다. 고치지 않고 남겼습니다. **사전 예상이 틀린 기록은 실패가 아니라 그 예상 모델이 어디서 어긋났는지에 대한 정보입니다.**

### 2.9 LLM Agent — 도구 호출과 평가

Agent는 LLM이 도구를 선택해 호출하고 결과를 바탕으로 답하는 구조입니다.

**OpenAI function calling 규약**: 모델이 `tool_calls`를 돌려주면, 각 호출의 결과를 `role: "tool"` 메시지로 `tool_call_id`와 함께 되돌려야 합니다.

**실제로 겪은 오류**: 도구 결과를 `user` 메시지로 전달했습니다. 그러자 모델이 자기가 이미 호출한 것을 보지 못하고 **같은 호출을 6번 반복**해 예산을 소진했습니다. 규약을 지키자 해결됐습니다.

**Agent를 어떻게 평가하나** — 이 프로젝트는 6개 축을 정의했습니다.

| 축 | 질문 |
|---|---|
| 도구 선택 | 기대한 도구를 부르고 금지한 도구를 피했나 |
| 주장별 인용 | 수치를 담은 모든 주장에 출처가 붙었나 |
| 정보 부족 선언 | 근거가 없을 때 모른다고 했나. 있을 때 불필요하게 포기하지 않았나 |
| 오류 처리 | 도구 실패를 수치 날조 없이 처리했나 |
| **종료** | 호출 예산 안에서 끝냈나 |
| 필수 고지 | 요구한 고지 문구를 답변에 넣었나 |

final 8문항 결과입니다.

| 정책 | 전 축 통과 | 약점 |
|---|---|---|
| 규칙 기반 | 8/8 | — |
| gpt-4.1 | 5/8 | 종료 6/8, 정보 부족 6/8 |
| gpt-5-mini | 4/8 | 종료 4/8 |

**도구 선택·인용·오류 처리는 두 모델 모두 8/8이었습니다.** 약점이 "언제 멈출지"에 몰렸습니다. 도구 범위 밖 질문(임상 3상 생존기간)에 gpt-4.1은 결론은 맞게 냈지만 5번 호출했고, 규칙 기반은 0번으로 끝냈습니다. **능력보다 절제의 문제입니다.**

**출처 검증 장치**: 답변의 모든 숫자가 도구가 돌려준 값에 있는지 정규식으로 검사했습니다.

```python
NUMBER = re.compile(r"(?<![A-Za-z])(?<![0-9.])\d+(?:\.\d+)?(?![0-9.])(?![A-Za-z])")
```

`IC50`의 `50`이나 `C797S`의 `797`을 측정값으로 세지 않도록 앞뒤 문자를 봅니다. 이 장치가 실제로 작동했습니다 — gpt-4.1이 도구가 준 `8.055`를 `8.06`으로 **반올림**해 적었고, 검증이 답변을 반려했습니다. 날조는 아니지만, 답변의 숫자가 도구의 숫자와 다르면 원 출처로 되짚을 수 없습니다.

**평가 설계의 함정**: 개발용 질문(dev)으로 정책을 고치고, 최종 질문(final)은 한 번만 돌려야 합니다. gpt-4.1은 dev 6/6이었지만 final 5/8이었습니다. **dev 점수를 성능으로 보고하면 과대평가입니다.**

그리고 이 프로젝트는 "규칙 기반이 LLM보다 낫다"고 결론 내리지 않았습니다. 질문 14개를 규칙 정책 설계자와 같은 사람이 만들었고, 규칙 정책은 도구 4개 밖으로 나갈 수 없으며(LLM은 `aspirin → CHEMBL25` 해석을 해냈습니다), 표본이 8문항입니다. **자기가 만든 시험에서 자기 정책이 이긴 것을 일반화하지 않는다**는 것이 결론입니다.

### 2.10 추론 서비스 — API 설계의 책임

FastAPI로 만든 엔드포인트입니다.

```
GET  /healthz     프로세스 생존
GET  /readyz      모델 로딩 + 해시 3개 일치 시 200, 아니면 503
GET  /model-info  모델·코호트·설정 해시, 학습 규모, 라벨 범위, 고지, 런타임 버전
POST /predict     SMILES 배열 → 분자별 예측·적용 범위 판정·고지
```

`healthz`와 `readyz`를 나눈 이유: 프로세스가 살아 있는 것과 모델이 제대로 로딩된 것은 다릅니다. 해시가 설정과 어긋나면 `readyz`가 503을 돌려줍니다. **다른 모델을 조용히 서비스하는 쪽이 멈추는 쪽보다 나쁩니다.**

**설계상 거부한 것들**입니다.

- 학습·재학습 엔드포인트 없음 — 서비스는 추론만 한다
- 고지 생략 옵션 없음 — 2.2절의 상수 붕괴가 이유다
- 해석 불가 SMILES에 `predicted_pIC50` **필드 자체를 넣지 않음** — 0이나 평균값으로 메우지 않는다
- 예측값을 `measured`나 `실측`으로 부르는 필드명 없음

응답은 `value_is_a_prediction_not_a_measurement: true`를 스스로 달고 나옵니다.

### 2.11 컨테이너와 재현성

**멀티플랫폼 이미지**: Docker 이미지는 플랫폼별로 다릅니다. manifest 인덱스(여러 플랫폼을 묶은 목록)의 digest를 `FROM`에 쓰면 `--platform` 플래그로 플랫폼을 고를 수 있습니다.

```dockerfile
FROM python:3.12.14-slim-bookworm@sha256:392307d2...3564e
```

태그(`:3.12.14-slim-bookworm`)는 같은 이름으로 내용이 바뀔 수 있습니다. digest로 고정해야 "다시 만들 수 있다"가 성립합니다.

**이미지 크기의 두 가지 의미**를 실제로 혼동했습니다.

| 측정 | arm64 | amd64 |
|---|---|---|
| 압축 해제 (`docker images`) | 829 MB | 805 MB |
| 압축 (레지스트리 저장) | — | 173.6 MB |

`docker image inspect --format '{{.Size}}'`가 173,608,921을 돌려줘 처음에 오해했습니다. Artifact Registry의 저장 크기가 정확히 173.612MB로 찍혀 그것이 **압축된 레이어 크기**임이 드러났습니다.

**빌드 컨텍스트**: `.dockerignore`를 **허용 목록 방식**으로 썼습니다 — 전부 제외하고 필요한 것만 되돌립니다.

```
*
!deployment/requirements-serve.txt
!src/egfr_lab/serving
...
```

거부 목록이면 새 폴더가 생길 때마다 빌드 컨텍스트에 조용히 섞입니다. 이 저장소는 공개이고 `data/`에 원자료 247MB가 있어, 빠뜨리는 쪽이 더 위험합니다.

### 2.12 클라우드 실행 — 측정 방법론이 결론을 바꾼다

Cloud Run에 배포해 실측한 결과입니다.

| 환경 | 서버 처리 p50 | 비고 |
|---|---|---|
| 로컬 호스트 (macOS arm64) | 8.426 ms | |
| 로컬 컨테이너 (linux/arm64) | 10.040 ms | 1.19배 |
| **Cloud Run (linux/amd64)** | **35.042 ms** | **4.2배** |

모델 로딩은 0.844초 → 4.998초로 **5.9배** 느려졌습니다.

런타임을 확인하니 `Linux-4.19.0-gvisor-x86_64`였습니다. Cloud Run은 **gVisor 샌드박스**에서 돕니다 — syscall을 사용자 공간에서 가로채므로 I/O가 많은 작업에 비용이 큽니다.

**원인을 gVisor 하나로 단정하지 않았습니다.** CPU 세대·클럭, 플랫폼(arm64→amd64), 샌드박스가 섞여 있고 분리 측정하지 않았습니다. 말할 수 있는 것은 "같은 코드·같은 모델·같은 라이브러리 버전으로 클라우드가 3.5~5.9배 느렸다"입니다.

**측정에서 반드시 분리해야 하는 것**이 있습니다.

| 측정 | p50 | 포함하는 것 |
|---|---|---|
| 클라이언트 왕복 | 50.019 ms | 네트워크 + TLS + 프런트엔드 + 서버 |
| 서버 처리 | 35.042 ms | 서버만 (`X-Process-Time-Ms` 헤더) |
| 차이 | 14.977 ms | 네트워크와 프런트엔드 |

왕복 시간을 서버 성능으로 쓰면 틀립니다. 약 15 ms가 네트워크입니다.

**콜드 스타트도 두 값이 다릅니다.** 첫 요청 왕복은 135 ms인데 모델 로딩은 4.998초였습니다. 모순이 아닙니다 — Cloud Run이 시작 프로브로 컨테이너를 먼저 준비시킨 뒤 트래픽을 넘기기 때문에, 요청 왕복에 로딩 시간이 포함되지 않습니다. **클라이언트 체감 콜드 스타트와 컨테이너 실제 시작 비용은 다른 값입니다.**

### 2.13 비용 — 요율을 손으로 적지 않는다

AWS 단계에서는 **공개 가격 API**에서 요율을 받아 응답 SHA-256과 함께 보존했습니다.

```
https://pricing.us-east-1.amazonaws.com/offers/v1.0/aws/AmazonECS/current/ap-northeast-2/index.json
```

블로그나 요약글의 수치는 리전과 시점이 어긋나기 쉽습니다. 서울 리전 Fargate ARM 요율은 vCPU·시간당 $0.03725, 메모리 GB·시간당 $0.00409였습니다(가격표 발행일 2026-10-19).

GCP는 가격 페이지 본문을 기계적으로 받지 못해(JS 렌더링) **무료 등급 수치를 2차 출처에 의존**했습니다. 두 단계의 증거 수준이 다르다는 것을 보고서에 밝혔습니다.

**과금 반영 지연**: 측정과 같은 날 비용 화면에서 $0을 봐도 "과금 없음"과 "아직 미반영"을 구분할 수 없습니다. 구분하는 방법은 비용 테이블에 해당 서비스 행이 나타나는지 보는 것입니다.

### 2.14 겪은 함정 모음 — 디버깅에서 배운 것

| 증상 | 원인 | 교훈 |
|---|---|---|
| 계산은 끝났는데 프로세스가 2시간 멈춤 | chemprop 워커가 종료되지 않음 (`os_waitpid` 블록) | `sample <pid>`로 네이티브 스택을 봤다. 워커 8 → 0으로 바꾸니 7배 빨라졌다 |
| `127.0.0.1:8000`이 다른 서비스를 응답 | 다른 프로세스가 IPv4로 포트 점유, Docker는 IPv6로 바인딩 | **엉뚱한 대상을 측정할 뻔했다.** 측정 전에 `/model-info` 해시로 대상을 확인하게 했다 |
| 파일 행 수가 1 적게 셈 | 파일 끝 개행이 없어 `wc -l`이 덜 셈 | 설정 파일을 고치면 `config_sha256` 검증이 깨지므로 보고서에 정정했다 |
| 빈 SMILES에 예측값 | RDKit이 빈 문자열을 원자 0개 분자로 파싱 | LLM이 예상 밖 입력을 보내 발견했다 |
| seed를 바꿨는데 결과가 같음 | chemprop v1의 `--seed`는 분할 시드 | `--pytorch_seed`가 모델 시드다 |
| PDF 렌더러 크래시 | 함수 파라미터 `header`와 표 파싱 지역변수 `header` 충돌 | 이름을 분리했다 |
| 줄바꿈 걸친 `**굵게**`가 별표로 출력 | 렌더러가 줄 단위로 처리 | 원고에서 한 줄로 유지하고 렌더러에 경고를 넣었다 |

## 3부. 더 공부하면 좋을 것

이 프로젝트에서 **다루지 않았거나 막힌** 영역입니다. 다음 단계의 후보입니다.

| 주제 | 왜 필요한가 |
|---|---|
| 중도절단 회귀 | 부등호 관측 5,482건을 버리지 않고 쓰는 방법 |
| 다중작업 학습 | 변이별·실험별 데이터를 함께 쓰면서 섞지 않는 방법 |
| 예측 구간 보정 | 점 추정이 아니라 "얼마나 모르는지"를 함께 내놓기 |
| 사전학습 분자 모델 | 22건 같은 소표본에서 전이학습의 효과 |
| 활성 학습 | 다음에 어떤 화합물을 측정하면 정보가 가장 큰가 |
| Cheng-Prusoff 보정 | ATP 농도가 다른 IC50을 조건부로 비교하는 방법 |
| 구조 기반 방법 | 도킹·자유에너지 계산 (이 프로젝트 범위 밖) |
| MLOps | 모델 레지스트리, 데이터 드리프트 감시, A/B 배포 |

그리고 이 프로젝트의 **근본 제약**은 하나입니다.

> 22건·12 scaffold로는 어떤 모델도 평균 예측을 확실히 넘지 못한다.

이를 풀려면 표본을 늘려야 하고, 그러려면 실험 조건이 같다는 것을 **원문으로** 확인해야 합니다. 선정 기준을 통과한 5,511건·558 assay가 대기 중이지만, 조건 동일성 확인이 막혀 있습니다. 데이터가 없어서가 아니라 **근거가 없어서** 쓰지 않았습니다.
