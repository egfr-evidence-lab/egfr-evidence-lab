# EGFR Evidence Lab — 정의와 결과

이 문서는 세 가지를 적습니다. **무엇을 확인하려 했는가**, **무엇을 미리 정의했는가**, **무엇이 확인됐는가**.

모든 수치는 저장소의 실제 산출물에서 왔습니다. 각 절 끝에 출처 경로를 적었습니다.

작성 2026-10-22 · 전체 테스트 81개 통과

## 1. 프로젝트의 정의

### 1.1 한 문장

> ChEMBL의 공개 EGFR 실험 데이터로 화합물 활성을 예측하고, 그 예측의 근거와 한계를 추적 가능하게 기록하는 프로젝트.

### 1.2 무엇이 목표가 아니었는가

이것을 먼저 적는 이유는, 목표를 좁게 정의하지 않으면 결과를 넓게 주장하게 되기 때문입니다.

| 목표가 아니다 | 이유 |
|---|---|
| 최고 성능 모델 만들기 | 데이터가 그것을 허용하지 않는다는 것이 결론 중 하나다 |
| 신약 후보 발굴 | 실험 검증 없는 예측은 후보가 아니다 |
| EGFR 활성 예측 서비스 | 학습 범위가 22건·12 scaffold다 |
| 논문 성능 재현 | 축소 조건으로 돌렸으므로 동일 조건 재현이 아니다 |
| LLM과 규칙 기반의 우열 판정 | 자기가 만든 시험으로 판정할 수 없다 |

### 1.3 확인하려 한 질문 6개

각 마일스톤은 하나의 질문에 대응합니다.

| 단계 | 질문 |
|---|---|
| **M1** | 공개 데이터로 만든 기준 모델이 평균 예측보다 나은가 |
| **M2** | 분자 그래프를 학습하는 D-MPNN이 수작업 fingerprint보다 나은가 |
| **M3** | 공개 논문의 벤치마크를 우리가 돌려도 비슷한 값이 나오는가 |
| **M4** | 기업이 보고한 EGFR 내성·분해제 사례를 원문 수준에서 검토할 수 있는가 |
| **M5** | LLM이 도구를 골라 쓰면서 근거 없는 수치를 만들지 않는가 |
| **M6** | 이 모델을 버전이 고정된 서비스로 만들어 클라우드에서 실제로 돌릴 수 있는가 |

### 1.4 이 질문들이 공유하는 전제

모든 질문에 **"확인할 수 없으면 확인할 수 없다고 적는다"**는 조건이 붙었습니다. 그래서 결과의 절반이 "미확정"입니다. 그것이 실패가 아니라 이 프로젝트의 산출물입니다.

## 2. 실행 전에 정의한 것

결과를 본 뒤 기준을 고치는 것을 막기 위해, 각 단계의 설정을 **실행 전에** JSON으로 동결하고 SHA-256을 기록했습니다.

### 2.1 데이터 선정 정책

`configs/cohort_policy.json` · `configs/project.json`

| 정의한 것 | 값 |
|---|---|
| 표적 | `CHEMBL203` (인간 EGFR) |
| 지표 | IC50 → pIC50 (등식 값만) |
| 라벨 단위 | nM 기준 환산 |
| 변이 정책 | 변이와 정상형을 섞지 않는다 |
| **모르는 변이** | **정상형으로 가정하지 않는다** (`unknown_variant_is_wild_type: false`) |
| 실험 종류 | 생화학과 세포 실험을 섞지 않는다 |
| 지표 혼합 | IC50·Ki·Kd를 섞지 않는다 |
| 억제·분해 | 억제 지표와 분해 지표를 섞지 않는다 |
| 원자료 | 원 응답과 제외 사유를 모두 보존한다 |

### 2.2 assay 병합(pooling) 조건

같은 표적의 다른 실험 결과를 합치려면 13개 필드가 모두 확인되고 같아야 한다고 정의했습니다.

```
species · variant · protein_construct · enzyme_concentration · atp_uM ·
substrate · substrate_concentration · preincubation_minutes ·
reaction_minutes · temperature_C · buffer_pH · readout · inhibitor_scope
```

추가 조건:

| 항목 | 기준 |
|---|---|
| 값이 빠진 경우 | **같다고 보지 않는다** |
| 공유 구조 최소 개수 | 5개 |
| 일치 허용 오차 | \|ΔpIC50\| ≤ 0.5 |
| 일치 비율 최소 | 0.75 (Wilson 95% 하한도 0.75) |
| 중앙값 편향 한계 | 부트스트랩 95% 구간이 ±0.3 안 |
| \|Δ\| > 1 비율 상한 | 0.1 |
| 묶음 내 모든 쌍 | 전부 통과해야 한다 |

마지막 줄의 기준 상태도 적었습니다 — "프로젝트의 사전 고정 운영 기준이며 EGFR에서 검증된 보편적 합격선이 아니다."

### 2.3 평가 설계

| 항목 | 정의 |
|---|---|
| **주 분할** | scaffold (Murcko 골격 단위) |
| 보조 분할 | random (분자 단위 그룹) |
| seed | 42, 123, 2026 |
| 주 지표 | MAE |
| 보조 지표 | RMSE, Spearman |
| 부트스트랩 | 2000회, **scaffold 단위** 재표집 |
| 신뢰수준 | 95% |
| **테스트셋 튜닝** | **금지** (`test_used_for_tuning: false`) |

scaffold를 주 분할로 **먼저** 정한 것이 중요합니다. 나중에 보겠지만, random 분할만 보면 결론이 달라집니다.

### 2.4 Agent 사양

`configs/agent_eval.json`

| 항목 | 값 |
|---|---|
| 도구 | 4개 (예측·실측 조회·문헌 검색·근거 조회) |
| 호출 예산 | 6회 |
| 검색 재시도 | 2회 |
| 출처 요구 | 필수 |
| **수치 날조** | **금지** (`llm_may_invent_measurements: false`) |
| 질문 분리 | 개발용 6문항 / 최종 8문항 |
| 최종 실행 | **한 번만** 돌리고 결과를 그대로 싣는다 |

정책 코드를 질문 파일보다 **먼저** 작성했다는 사실도 기록했습니다. 질문에 맞춰 정책을 쓰지 않았다는 증거입니다.

### 2.5 서비스 계약

`configs/serving_m6.json`

설계상 **거부한 것**을 명시했습니다.

- 학습·재학습 엔드포인트
- 고지 생략 옵션
- 변이형·세포 실험·분해제 지표 예측
- 예측값을 "측정값"으로 부르는 필드명

### 2.6 금지 목록

각 설정 파일에 `forbidden` 항목을 두었습니다. 실제로 적은 것들입니다.

- 최종 질문의 점수를 본 뒤 정책을 고치고 그것을 최초 결과처럼 쓰는 것
- 규칙 기반 정책의 결과를 "LLM Agent를 평가했다"고 쓰는 것
- 지연시간 측정을 보고 사전 예상을 고친 뒤 맞췄다고 쓰는 것
- 컨테이너 검증만 하고 "클라우드 배포 완료"라고 쓰는 것
- 과금 $0을 "비용을 측정했다"로 쓰는 것
- 무료 등급 수치를 1차 출처에서 확인했다고 쓰는 것

데이터가 없어서가 아니라 **근거가 없어서** 쓰지 않았습니다. 이것이 이 프로젝트의 가장 큰 제약이고, 가장 의도적인 선택입니다.

## 4. 결과 — 질문별 답

### 4.1 M1 — 기준 모델이 평균 예측보다 나은가

**답: 확정할 수 없다.**

scaffold 분할(주 지표), 22건, seed 3개:

| 모델 | MAE (42 / 123 / 2026) |
|---|---|
| Dummy (평균 예측) | 0.3096 / 0.3096 / 0.3096 |
| Morgan-RF | 0.2950 / 0.3001 / 0.2925 |

RF가 약간 낮습니다. 그런데 차이의 95% 구간은:

| seed | RF−Dummy | 95% 구간 | 0 포함 |
|---|---|---|---|
| 42 | −0.0146 | −0.0819 ~ +0.0506 | 예 |
| 123 | −0.0095 | −0.0766 ~ +0.0639 | 예 |
| 2026 | −0.0170 | −0.0906 ~ +0.0513 | 예 |

**세 seed 모두 구간이 0을 포함합니다.** 이 데이터로는 우위를 확정할 수 없습니다.

**분할 방식이 결론을 바꿉니다.** random 분할 seed 42는 구간 상한이 −0.0047로 0을 넘지 않습니다. 주 지표를 **먼저** scaffold로 정해두지 않았다면 유리한 쪽을 고를 수 있었습니다.

출처: `reports/baseline_pilot_20261020_v2/`

### 4.2 M2 — D-MPNN이 fingerprint보다 나은가

**답: 구별되지 않는다.**

| 모델 | scaffold MAE |
|---|---|
| Dummy | 0.3096 |
| D-MPNN | 0.3090 ~ 0.3111 |
| Morgan-RF | 0.2925 ~ 0.3001 |

paired 비교 **12개 중 11개**의 95% 구간이 0을 포함했습니다.

**원인을 찾았습니다.** D-MPNN 예측값의 표준편차가 0.011~0.036이었습니다. 관측 라벨의 표준편차는 0.377입니다. Spearman은 6개 설정 전부 음수였습니다.

**상수 붕괴**입니다. 모델이 입력을 보지 않고 평균 근처를 내놓는 해로 수렴했습니다.

구현에서 겪은 오류도 기록했습니다 — Chemprop v1의 `--seed`는 데이터 분할 시드이고 모델 시드는 `--pytorch_seed`입니다. 바로잡기 전 seed 간 예측 차이가 7.2e-05였고, 바로잡은 뒤 4.0e-02가 됐습니다.

출처: `reports/dmpnn_pilot22_20261021_v2/`

### 4.3 M3 — 공개 벤치마크를 재현할 수 있는가

**답: 저자값과 구별되지 않는 결과가 나왔다. 단 동일 조건 재현은 아니다.**

SAMPL 물-옥탄올 logP, RMSE:

| 세트 | 우리 측정 | 저자 보고 | 판정 |
|---|---|---|---|
| SAMPL6 | 0.3666 | 0.27 | 저자값이 우리 95% 구간 안 |
| SAMPL7 | 0.6843 | 0.49 | 저자값이 우리 95% 구간 안 |
| SAMPL9 | 1.0530 | 1.11 | 저자값이 우리 95% 구간 안 |

**세 세트 모두 저자 보고값이 우리 측정의 부트스트랩 95% 구간 안에 들어왔습니다.** 구별되지 않는다는 뜻입니다.

**동일 조건이 아닌 점**을 명시했습니다 — 축소한 조건(에폭·앙상블 규모 등)으로 돌렸고, 저자 환경(Linux·NVIDIA·Python 3.7)과 다릅니다. 그래서 "재현했다"가 아니라 "축소 조건에서 구별되지 않는 결과를 얻었다"로 적었습니다.

실행 중 장애도 기록했습니다 — 계산이 끝났는데(`Elapsed time = 1:58:48`) 프로세스가 2시간 종료되지 않았습니다. `sample <pid>`로 네이티브 스택을 떠서 워커 종료 대기를 확인했고, `--num_workers 0`으로 바꾸니 29초에 정상 종료됐습니다.

출처: `reports/sampl_repro_20261021_v2/`

### 4.5 M5 — LLM이 근거 없는 수치를 만들지 않는가

**답: 도구 선택·인용·오류 처리는 통과했다. 약점은 언제 멈출지였다.**

final 8문항, 6개 축:

| 축 | 규칙 기반 | gpt-4.1 | gpt-5-mini |
|---|---|---|---|
| 도구 선택 | 8/8 | 8/8 | 8/8 |
| 주장별 인용 | 8/8 | 8/8 | 8/8 |
| 오류 처리 | 8/8 | 8/8 | 8/8 |
| 정보 부족 선언 | 8/8 | 6/8 | 8/8 |
| 필수 고지 | 8/8 | 7/8 | 7/8 |
| **종료** | 8/8 | **6/8** | **4/8** |
| **전 축 통과** | **8/8** | **5/8** | **4/8** |

**출처 검증 장치가 실제로 작동했습니다.** gpt-4.1이 도구가 준 `8.055`를 `8.06`으로 적어 답변이 반려됐습니다. 정확히 말하면 **날조가 아니라 반올림**입니다. 없는 값을 만든 게 아니라 있는 값을 변형했습니다. 그래도 답변의 숫자가 도구의 숫자와 다르면 원 출처로 되짚을 수 없어 막았습니다.

이 건을 고치지 않았습니다. 검증 규칙을 느슨하게 하면 final 점수를 사후 조작하는 것이 됩니다.

**일반화하지 않습니다.** 질문 14개를 규칙 정책 설계자와 같은 사람이 만들었고, 규칙 정책은 도구 4개 밖으로 나갈 수 없으며(LLM은 `aspirin → CHEMBL25` 해석을 해냈습니다), 표본이 8문항입니다.

**dev가 final을 과대평가했습니다.** gpt-4.1은 dev 6/6 → final 5/8이었습니다.

**개발 중 발견한 내 결함 3건**도 기록했습니다.

| 증상 | 성격 |
|---|---|
| 빈 SMILES에 pIC50 8.057 | 내 도구 버그. 규칙 정책으로는 드러낼 수 없었고 LLM이 발견했다 |
| 같은 호출 6회 반복 | 내 프로토콜 오류. OpenAI `tool_calls` 규약 미준수 |

## 8. 남은 것

### 8.0 정의했지만 실행하지 않은 것

이것을 먼저 적습니다. 설정 파일에 `required`로 적힌 것과 실제 산출물이 어긋나면 기록의 신뢰가 떨어집니다.

| 항목 | 어디에 정의 | 실행하지 않은 이유 |
|---|---|---|
| **학습곡선** | `cohort_policy.json`의 `learning_curve_and_scaffold_coverage_required: true` | 22건에서 샘플을 줄이면 scaffold 분할이 성립하지 않는다. 15건이면 scaffold 8~9개, 10건이면 5~6개, 5건이면 2~3개다. 이미 22건에서 구간이 0을 포함하므로 더 작은 표본에서는 **곡선의 기울기 자체를 추정할 수 없다** |
| **scaffold 커버리지** | 같은 항목 | 규모와 무관하게 가능했고 새 정보를 줄 수 있었다. **미실행 이유는 우선순위 판단이며 불가능해서가 아니다** |
| **Chemprop v2** | `docs/03_tech_stack.md` · `pyproject.toml`의 `deep` extra | M3 재현이 저자 환경의 v1.6.1을 요구했고, M2도 같은 환경으로 통일해 버전 차이가 결과에 섞이지 않게 했다. 문서를 2026-10-22에 정정했다 |
| BM25·임베딩 문헌 검색 | `pyproject.toml`의 `literature`·`dense` extra | 정확한 식별자 조회로 충분했고 검색 품질을 평가할 질의 집합을 만들지 않았다 |
| MLflow 상시 운영 | `tracking` extra | JSON 매니페스트로 충분했다. 처음부터 "필요 시"로 적어 둔 항목이다 |
| model card | 관행 | 내용은 보고서와 manifest에 있으나 표준 형식으로 모으지 않았다 |

**학습곡선을 기계적으로 실행하지 않은 판단 자체를 기록했습니다.** 예상된 결과("전 구간에서 구별 불가")를 하나 더 추가하는 것보다, 실행이 무의미한 이유를 남기는 쪽을 택했습니다. 코호트가 늘어나면 이 판단은 무효입니다.

기록 위치: `configs/cohort_policy.json`의 `learning_curve_decision_20261022` · `configs/portfolio_scope.json`의 `defined_but_not_executed_20261022`

`src/egfr_lab`의 `evaluation`·`features`·`literature` 패키지는 비어 있었고 docstring이 "Planned"로 남아 있었습니다. 세 기능이 실제로는 `modeling`·`agent.tools`·`scripts`에 구현돼 있어, 각 패키지에 **구현 위치를 적었습니다.**

### 8.1 외부 조건이 막은 것

| 과제 | 상태 |
|---|---|
| **M4** 기업 문헌 사례 | **보류** — 원문 유료. 외부 조건이 바뀌어야 재개 |
| 코호트 확대 (furan45) | 보류 — 방법론 원문 미확보, 프로토콜 5개 항목 미확인 |
| 코호트 확대 (patent64) | 보류 — 구조 검증 0행, MS 불일치 13건 |
| 보류 목록 5건 | `CHEMBL2439336` · `CHEMBL5638807/14/15` · `CHEMBL5736995` |
| 과금 금액 확정 | 2026-10-23 이후 비용 테이블 재확인 |
| M5 다음 반복 | 반올림 허용 여부, 종료 개선, 질문 집합을 다른 출처에서 작성 |

### 8.2 설계해 두었으나 새 마일스톤 규모인 것

**부등호 관측 5,482건을 분류 과제로 쓰는 것**입니다.

회귀는 assay 조건에 민감해서 pooling이 막혔습니다. 그런데 `>10000 nM`(10 µM까지 올려도 50% 억제 없음)을 "비활성" 라벨로 쓰면, **조건 민감도가 훨씬 낮은 과제**가 됩니다. ATP 농도가 1 µM이든 10 µM이든 10 µM에서 안 듣는 화합물은 강한 저해제가 아닙니다.

그러면 원문 검증 없이도 수천 건 규모를 쓸 수 있습니다. **22건 벽을 우회하는 유일한 경로로 보입니다.**

단 이것도 가정입니다. "조건 민감도가 낮다"를 먼저 검증해야 합니다 — 같은 화합물이 여러 assay에서 활성/비활성으로 갈리는 비율을 재면 됩니다. 그 데이터는 이미 있습니다.

### 8.1 근본 제약 하나

> 22건·12 scaffold로는 어떤 모델도 평균 예측을 확실히 넘지 못한다.

M2의 D-MPNN 상수 붕괴와 M6의 RF 상수 붕괴가 같은 뿌리로 의심됩니다. 이를 풀려면 표본을 늘려야 하고, 그러려면 실험 조건 동일성을 원문으로 확인해야 합니다.

선정 기준을 통과한 5,511건·558 assay가 대기 중입니다. **데이터가 없어서가 아니라 근거가 없어서** 쓰지 않았습니다. M4·furan45·patent64가 모두 같은 벽에 막혀 있습니다 — 유료 논문과 특허 원문입니다.

## 9. 이 프로젝트가 실제로 보여주는 것

모델 성능은 입증되지 않았습니다. 그런데 이 프로젝트가 보여주는 것은 다른 것입니다.

1. **공개 데이터의 함정을 실제로 밟고 기록했다** — 부등호 5,482건, 변이 미지정 115건, 품질 경고 510건, 중복 의심 2,744건, 조건 불일치로 pooling 0쌍
2. **결과를 과장하지 않는 장치를 만들고 지켰다** — 설정 사전 동결, 사전 예상 등록, 주 지표 우선 지정, 금지 목록, 독립 검산
3. **사전 예상이 틀린 것을 그대로 남겼다** — M6에서만 4건
4. **자기 결함을 기록했다** — Agent 개발 중 3건, M6에서 2건, 측정 대상 오인 1건
5. **막힌 것을 막혔다고 적었다** — M4, 코호트 확대 2건, 과금 금액
6. **예측값에 한계를 붙여야 하는 이유를 실증했다** — 적용 범위 밖 상수 붕괴
7. **정의했지만 실행하지 않은 것을 모아 적었다** — 6건. 그중 학습곡선은 실행이 무의미한 이유를, scaffold 커버리지는 "가능했지만 우선순위에서 밀렸다"를 구분해 기록했다

7번이 가장 불편한 항목입니다. 꼼꼼함을 내세우는 프로젝트에서 `required: true`와 실제가 어긋난 것을 발견했습니다. 지우는 대신 이유와 함께 남겼습니다.

면접에서 "왜 22건인가"를 물으면 답이 준비돼 있습니다. **5,511건이 기준을 통과했지만 조건 동일성을 원문으로 확인하지 못해 쓰지 않았습니다.**
